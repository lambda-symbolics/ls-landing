Goals and verified missions

Use a goal for work that can continue between messages. Use a mission if you want to define acceptance criteria, checks, and a budget before work begins.

Set a goal

  1. Run (goal "OBJECTIVE") to set the objective.
  2. Run (goal) to check progress. Use (goal :pause) to pause, or (goal :resume) to continue.

By default, a goal pauses after eight automatic turns without a new message from you. Change this limit with (settings :goal-continuation-limit N).

Start and verify a mission

  1. Install the objective, limits, and acceptance criteria with (mission :start specification). This example requires both a passing build and your review:

    Common Lisp 
    (mission :start
 '(:objective "Deliver the accepted build"
   :turn-limit 40 :token-limit 100000 :wall-seconds 3600
   :criteria ((:id "build" :description "The build passes" :gates ("build"))
              (:id "review" :description "The user accepts the result"))
   :gates ((:id "build" :kind :command :command "make check"
            :inputs ("Makefile" "src/main.lisp") :deterministic-p t
            :attempt-limit 3 :timeout-seconds 300))))

  2. Run (mission :run) and inspect the saved state with (mission :status).

  3. Give explicit evidence for each criterion without a gate. If the mission is blocked on your review, accept the result and resume:

    Common Lisp 
    (mission :accept "review" "I inspected the artifact and accept the result")
(mission :resume)

  4. Request verification with (mission :verify). The model can also request it with its completion marker. A mission is verified only if every gate passes and every criterion is satisfied.

Give each criterion a unique :id and a :description. Use :gates to list the checks that count as evidence for that criterion. The model cannot weaken the criteria or accept results on your behalf. Only the primary agent can use the mission.status, mission.verify, mission.stop, and mission.invalidate tools.

Set a budget

Mission budgets cover work by the primary agent and by child agents.

  • Turns. Set :turn-limit to cap provider calls.
  • Tokens. Set :token-limit to cap model usage. This is not a billing limit.
  • Time. Set :wall-seconds to set a deadline. It includes time spent paused.

Autolith pauses new inference if it cannot account for missing usage. Set :unknown-usage-policy :record at the start of the mission if you want work to continue with those gaps recorded.

  • Pause with (goal :pause) and resume with (mission :resume). These commands do not reset the budget.
  • Cancel with (mission :cancel).

Choose checks for acceptance

Gates run in order and stop at the first failure:

  • Command gates use the normal shell authorization and sandbox boundary.
  • Artifact gates require :path. Set :sha256 to check an expected hash.
  • Lisp gates require a :predicate string. The assertion runs in the existing isolated Lisp worker.

Use :timeout-seconds and :attempt-limit to set the time and attempts for each check.

For checks that depend on files, use :deterministic-p t and list all relevant files in :inputs. For checks that depend on remote state, run the check again after the remote state changes:

Common Lisp 
(mission :invalidate "build" "The remote build configuration changed")

Invalidating a check allows it to run again if there are attempts left in the budget.

Independent review checkpoints

Attach a reviewer to an active mission with mission-review.configure, or evaluate:

Common Lisp 
(application-mission-review-configure
 *active-application*
 '(:id "release-review" :phase :final-acceptance
   :inputs ("src/main.lisp" "tests/main-tests.lisp")
   :context "Review the changed behavior and test coverage. Report concrete findings."
   :turn-limit 4 :token-limit 16000 :run-limit 3))

List the files that the reviewer should inspect in :inputs. Set :run-limit to cap the number of changed snapshots reviewed.

  • Run a checkpoint with mission-review.trigger and the checkpoint ID.
  • Read the findings with mission-review.inspect.
  • Use mission-review.decide to resolve or reject each finding. Give evidence for the decision.

Final verification runs the checkpoints configured for final acceptance. Resolve outstanding findings and retry interrupted reviews before acceptance.

Scheduled mission continuations

Use mission-schedule.add to schedule a continuation. Give the schedule a unique ID and say what Autolith should do. Choose one trigger:

  • :at sets a date and time in Common Lisp universal time.
  • :interval sets an interval in seconds.
  • :event names an external event.
Common Lisp 
(application-mission-schedule-add
 *active-application* :id "build-followup"
 :content "Check the pending build and continue the mission."
 :at (+ (get-universal-time) 300) :missed-policy :latest)

For recurring schedules, select a missed policy:

  • latest runs the newest missed occurrence. This is the default.
  • all runs every missed occurrence.
  • skip skips missed occurrences.

A time schedule pauses automatic goal turns between occurrences. You can still send a message. Scheduled work uses the existing mission budget.

Occurrences that come due while the mission is paused or blocked are skipped. After you resume, the next occurrence runs at the scheduled time.

  • Use mission-schedule.inspect to see pending or skipped occurrences.
  • Use mission-schedule.cancel with the schedule ID to cancel future work.

If scheduled work stopped partway through, check what it did before you retry. Use mission-schedule.resolve to record the outcome or request a retry.
