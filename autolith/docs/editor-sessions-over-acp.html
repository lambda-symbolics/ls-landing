Editor sessions over ACP

To open an ACP editor session:

  1. Authenticate the selected provider with autolith auth.

  2. Configure your ACP-compatible editor to launch:

    Shell 
    autolith acp

  3. Open a session in the editor. ACP uses UTF-8 JSON-RPC on stdin and stdout. Diagnostics go to stderr.

Open an editor session in the directory where you want to work. To resume it, reopen the same session ID in the editor or use autolith open ID in a terminal.

Manage the editor session

  • Approvals. Answer prompts in the editor or terminal. To change the default behavior, choose a permission mode in the editor or launch ACP with --permissions auto|sandbox|full.
  • MCP servers. Supply servers before opening a new session. To change the list of servers supplied by the editor, open a new session.
  • Closing. Cancel the prompt to stop the current turn. Close the session to disconnect the editor.

Remote clients

  • Use autolith acp --http for an HTTP or WebSocket client.
  • Use autolith acp --websocket for a WebSocket-only listener.

Both listen on 127.0.0.1:8737 by default. Supply a port or a host and port to change the listener:

Shell 
autolith acp --websocket 9000
autolith acp --http 0.0.0.0:8737 --token "$ACP_TOKEN"
autolith acp --http [::1]:8737

Copy the endpoint URL from the terminal into your client. Press Ctrl-C to stop the server.

For remote access, put a TLS reverse proxy in front of the listener and require a token.

Use Authorization: Bearer TOKEN if the client supports headers. Otherwise, add ?token=TOKEN to the URL.
