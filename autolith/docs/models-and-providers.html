Models and providers

Sign in and choose a model

  1. Run autolith auth PROVIDER. Replace PROVIDER with the provider name. In a session, use (auth "PROVIDER").
  2. Follow the sign-in prompt. For an API provider, paste your key at the hidden prompt.
  3. Run (models) to refresh the list, then (model) to choose a model.
  • chatgpt uses your ChatGPT subscription. Use autolith auth chatgpt device if you need a device code.
  • openai-api uses an OpenAI API key.
  • copilot uses your GitHub Copilot subscription. Pick copilot/auto on Student or Free plans. For GitHub Enterprise Cloud with data residency, set AUTOLITH_COPILOT_DOMAIN to your TENANT.ghe.com hostname before sign-in and subsequent launches.
  • For OpenCode, use opencode-go or opencode-zen according to your plan.
  • Use gemini for the Gemini subscription. For Google Vertex AI, sign in with gcloud auth application-default login, set GOOGLE_CLOUD_PROJECT and GOOGLE_CLOUD_LOCATION, then choose a model from vertex-gemini or vertex-anthropic.

Use autolith models to list locally known models. Use (model "PROVIDER/MODEL") to save a choice or autolith --model PROVIDER/MODEL to choose a model for one launch. To pass an exact catalog ID, use --provider PROVIDER --model MODEL.

If you use ChatGPT and want faster replies, try (settings :codex-fast-mode-p t). Fast mode is available for supported models and counts more heavily against plan usage.

Run a local model with Ollama

Use a model that supports tool calls if you want Autolith to read files or run commands.

  1. Start ollama serve if Ollama is not running. Download the model in another terminal:

    Shell 
    ollama pull qwen3:8b

  2. Add this form to ${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp:

    Common Lisp 
    (register-openai-compatible-provider
 :name                         "local-ollama"
 :endpoint                     "http://127.0.0.1:11434/v1/chat/completions"
 :models                       '("qwen3:8b")
 :api-key-environment-variable "AUTOLITH_OLLAMA_KEY"
 :stream-usage-p               nil)

  3. Set a nonempty key and start Autolith. Local Ollama ignores the key, so you can use ollama as the value.

    Shell 
    export AUTOLITH_OLLAMA_KEY=ollama
autolith models | grep -Fx 'local-ollama/qwen3:8b'
autolith --provider local-ollama --model qwen3:8b
  4. Send a short prompt to check that the reply streams. Ask Autolith to list the files in the current directory to check tool calls.

Troubleshoot Ollama

  • Unknown model. Run ollama list and copy the exact ID into :models.
  • Rejected stream options. Set :stream-usage-p nil as shown above.
  • Context limit is too small. Raise the limit on the server first. Then set :models to a list such as '((:name "qwen3:8b" :context-window 32768)), using the limit you set on the server.

Add another OpenAI-compatible provider

Use register-openai-compatible-provider in init.lisp for services that support streaming Chat Completions. Adapt the Ollama example:

  1. Choose a unique :name and set :endpoint to the full Chat Completions URL.
  2. List model IDs in :models, set :models-endpoint to the full model list URL, or set both. List an ID explicitly if you want to select it on the first launch.
  3. Restart Autolith. Set the environment variable you named in :api-key-environment-variable or save a key with autolith auth PROVIDER. If both are set, Autolith uses the environment variable.
  4. Run (models :provider "PROVIDER") to refresh the catalog. Select a model with (model "PROVIDER/MODEL").
