Talk to Autolith

Prose, Lisp, and commands

Type a request in plain text to send it to the current channel. For example, ask Autolith to review a change and name the file or test you want it to check. Type @ to complete a workspace path or a participant handle. A token that contains a slash is treated as a path.

Start input with ( to evaluate Common Lisp in the active image. Autolith passes the form and its result to the model. The form has its normal effects in that image. To send text from a file, or to attach an image, use channel.send:

Common Lisp 
(channel.send :text (read-file "request.org"))
(channel.send :channel "@test-review" :text "Run the focused tests.")
(channel.send :text "Review this diagram" :images #("/tmp/diagram.png"))
  • Run (help) for an overview, or (help :commands) for a list of commands.
  • Use (help :conversations) for a topic, or (help 'open) for the arguments of a command.
  • Press Tab after a command name and a space to complete an argument.

Run Lisp in the background

Type ?, a space, and one Lisp form. This runs the form without starting a model turn.

Common Lisp 
? *package*
? (progn (sleep 10) (values :finished 42))

Replace exec:1 in these examples with the job ID you receive:

  • Inspect it with (job.get :id "exec:1").
  • Wait for it with (job.wait :id "exec:1").
  • Cancel it with (job.cancel :id "exec:1").

Recover from a command error

  1. Choose Ask Autolith why this failed in the restart picker.
  2. Review the proposed recovery before you choose a restart. A retry does not undo earlier effects.
  3. Press Escape to return to the picker from diagnosis. Press Escape in the picker to abort the operation.

Interrupt a turn

  • Press Escape to cancel the turn and allow queued input to proceed.
  • Press Ctrl-C to cancel the turn and pause queued work until you submit new input.

Command arguments

Pass Lisp values directly to commands:

  • Use keywords for actions, such as :refresh in (mcp :refresh).
  • Use t to enable a setting and nil to disable it. Omit the value to inspect the setting.
  • Use numbers for quantities and strings for text or identifiers. Pass pathnames and quoted Lisp data directly rather than spelling them out in strings.
Common Lisp 
(settings :boot-screen-seconds 2)
(settings :reasoning-traces-p t)
(settings :reasoning-traces-p nil)

Automatic permissions

Choose a permission mode for the channel:

  • (permissions :ask) prompts for approval. Choose once for one operation or always to approve the exact operation for future calls.
  • (permissions :auto) classifies operations without an approval prompt. While Autolith classifies the call, look for judging in the status bar. Read the decision beside the tool call.
  • Use (permissions :sandbox) for sandboxed execution on supported platforms.
  • Use (permissions :full) to run with your full user privileges.

The mode is stored locally and restored when you reopen a saved channel. This includes full access, even after a restart.

Read the transcript

Read the transcript above the prompt. The status line shows LIVE if you are following new output.

  • Press PageUp or PageDown to scroll by a page.
  • Use Ctrl-PageUp or Ctrl-PageDown to jump between messages.
  • Use Ctrl-Home or Ctrl-End to jump to the oldest or newest position in the loaded transcript.

Run (history) to load earlier messages if you have reached the top of the loaded transcript.

Recall input and copy text

  • Use input history to recall your own messages, commands and Lisp forms.
  • Drag across the transcript to copy text. Hold Shift while dragging to select rows in the terminal emulator instead.
  • Use ⧉ copy below a code block to copy the source.
  • Click a tool call to insert the Lisp form at the prompt. Edit the arguments before you submit the form if you want a different call.
  • Click a lisp.eval input block to expand or collapse the source.

Look for ▸ while a tool call is pending, ✓ after success, and ! after failure. Read any error below the call. Thanks to @rgbcube for suggesting these markers.

Terminal diagrams

Ask for a fenced mermaid block to see a diagram in the terminal. Clermaid documents the supported syntax for:

  • Flowcharts
  • Sequence diagrams
  • Flat state diagrams
  • Class diagrams
  • Entity relationship diagrams
markdown 
```mermaid
flowchart LR
  A[Read] --> B[Evaluate]
  B --> C[Print]
```

While the response streams, read the Mermaid source in the live tail. Use the copy action on the finished diagram to copy the source. If the syntax is unsupported or the diagram is too wide, read the source block instead.

Parking and editing queued input

  1. Run (vault-store) to park queued work and unconsumed steering. Work already in progress continues.
  2. Run (vault-contents) to inspect the parked entries in restoration order. Entries are zero-indexed. Use setf to publish a change.
  3. Run (vault-restore) to put the edited entries at the front of the live queue.
Common Lisp 
(vault-store)
(vault-contents)
(setf (vault-contents 0) '(:message "Run the unit tests first."))
(vault-restore)

Use (vault) for a summary. To replace the entire list, set (vault-contents) without an index. Its entries may be (:message INPUT), (:command TEXT), (:lisp SOURCE) or, for scheduled wakeups, (:native-lisp SOURCE). Set the list to nil to clear it.

Managed resources

  1. Read the resource with resource.read.
  2. Pass the revision from the read as :base-revision to resource.edit.
  3. If the edit was rejected because the resource changed, read it again and check the new contents before editing.
Common Lisp 
(resource.read :uri "workspace:README.md")
(resource.read :uri "channel:current" :query "unit tests" :max-results 5)
(resource.read :uri "channel:current" :start-sequence 120 :record-count 10)
Resource Use
channel:current Read recent history, including records from before compaction.
channel:id/ID Read the history of one other channel.
channel:list Find channels and their participants. Reading does not subscribe you.
papercut:current List active reports about the running Autolith harness or its tools.
papercut:id/ID Read one papercut. Percent-encode the stable ID if necessary.

Search within a single channel. If you have a sequence number, pass it as :start-sequence to read from that point.

Memories

Use a note for preferences or conventions. Use a fact to record a value and the evidence for it.

Common Lisp 
(memories)
(memories "deploy")
(memory "3afbfa1a")
(forget "3afbfa1a")

Open the memory manager with (memories).

  • Press / to search.
  • Use Tab to switch between All, Notes and Facts. Use Shift-Tab to choose a scope.
  • Press n to create a note, e to edit one or d to forget the selected entry.

Use (memory "ID") to see the evidence. If a source changes, check it before relying on a note marked stale.

Facts and rules

Facts record values and their sources. Rules derive new facts from those values. For example, a rule can mark a pull request ready for review after the required checks pass.

  • Use (why "ID") to inspect the sources and rules behind a fact.
  • Use (what-changed) to see which facts changed and why.
  • Use (forget "ID") to retract an assertion.

Plans, methods, gates, and contracts

Use facts for work that depends on evidence you can check, such as whether a pull request can be merged.

  • A method describes how to do a task. Ask Autolith to use plan.expand to turn a task into steps.
  • A fact gate checks a claim before mission acceptance. Use one to require evidence that the reviewed changes passed CI.
  • A tool contract defines what must be true before a tool runs, or what the result establishes.

Learned procedures

Autolith can learn a procedure from repeated work. Run (procedures) to see the calls, inputs and status of learned procedures.

Common Lisp 
(procedures)
(admit-procedure "make-sales-report")
(run-procedure "make-sales-report" :file "q5")
(retire-procedure "make-sales-report")
  • Review and admit a procedure before reuse. Tool approvals still apply.
  • Use (retire-procedure "NAME") to prevent further runs.

Diagnosis

Ask Autolith to compare possible causes of a failure. With structured knowledge enabled, it can use diagnosis.run to compare hypotheses with recorded facts and tool results.

Exporting and importing data

Export a workspace from the OS shell, then import it at its new path:

Shell 
autolith data export project.sexp --workspace /home/al/code/project
autolith data import project.sexp --workspace /home/al/src/project

Use the same archive format at the Autolith prompt:

Common Lisp 
(data.export "project.sexp" :workspace "/home/al/code/project")
(data.import "project.sexp" :workspace "/home/al/src/project")

Use export to move conversations and workspace knowledge together. Copy the archive if you are moving to another machine.

Choose a new file for each export. If the import reports a conflict, review the conflicting record before retrying.

Session titles and resume

Autolith starts a channel title from your first message. Run (rename "NAME") to name the current agent yourself.

  • Run (channel-id) to find the stable ID of the current channel.
  • Run (open) to pick a channel or (open "ID") to open it directly.
  • Run (delete) to remove the displayed channel, or (delete "ID") to choose another. Confirm only if you intend to remove its history and child channels. The subtree must be idle and free of other attached clients.

Open an existing channel to return to the transcript and any retained jobs.

Usage

Run (status) or its alias (usage) at the Autolith prompt for model usage:

  • Token usage sums recorded input and output for this conversation. The prompt-cache row shows cache usage when reported by the provider.
  • Context is the current space used in the model window, not the sum of tokens sent over the conversation.
  • Cost covers recorded requests in this process. Review any unpriced request count before treating the total as a bill. Subscription rate limits are shown when available.

Run autolith usage from the shell to inspect stored conversations and disk usage.

Local sessions

Starting and switching channels

An interactive autolith launch starts the background server if needed and serves the inbox. Use the following shell commands to work on a channel:

Shell 
autolith open
autolith open researcher --read-only
autolith open /researcher/reviewer
autolith new /home/al/code/project
autolith new /home/al/code/project --detached

Without a target, autolith open opens the last changed top-level channel in the current workspace or creates one if there is none. Use autolith new for a fresh channel; add -d or --detached to create it without attaching. To open it later, use the printed autolith open ID command. Only one terminal can control a channel. Use --read-only to observe from another terminal.

Inside Autolith, use (open "ID") to switch channels. Use (detach) or Ctrl-Z to disconnect the terminal and leave work running. Use (exit) to end the channel. To stop all channels and their server, use autolith stop from the OS shell or (stop-server) from Autolith. Updating or rolling back also stops the shared server.

Checkpoints and launch options

Run (checkpoint) to save the shared process. Work already in progress finishes first, across all channels. New turns wait until after the save. Terminals reconnect automatically, and the requesting channel receives the generation ID. On Windows, the launcher restarts the server from the saved heap.

If you lose a connection unexpectedly, press r or Enter to retry the same channel, enter an ID to switch, or press q to detach. Retrying does not resubmit your work.

Use --model, --permissions or --immutable when creating a channel. Pair --provider with --model. When opening an existing channel, the only launch override you can pass is --permissions, and only when no terminal controls it. To choose a permission mode in the channel, run (permissions).

Channel sidebar

Expand home to see channels by repository or workspace.

  • Press Ctrl-S to toggle the sidebar. On a narrow terminal it opens as a drawer.
  • Click the sidebar or press Ctrl-Space (Ctrl-Tab where supported) to focus it. Use the arrows to select or expand an entry, Enter to open it, or Delete to remove it after confirmation.
  • Type to filter by agent name, ID, title or workspace. Press Escape to clear the filter or return focus to the transcript.
Marker Meaning
▌ Current channel in this terminal
▸ / ▾ Closed or open group
● / ○ Agent working or hosted but idle
· / ? No running session or unknown status

A yellow number counts messages received since this terminal last viewed the channel. @ counts mentions, and N pending counts deliveries waiting for a channel that is not loaded.

Session endpoints

Run autolith status to list active local sessions. Add --sexp if you need to read the output from Lisp.

Shell 
autolith start
autolith tell researcher 'Review the failing unit test.'
autolith tell /researcher/reviewer '(channel-id)'
autolith pause researcher
autolith detach researcher
  • Use autolith start to start the server in the background.
  • Send input to another channel with autolith tell.
  • Use autolith pause to cancel active work and pause queued work, or autolith detach to disconnect the terminal.

With autolith tell, input that begins with ( is evaluated as Lisp. Supply the arguments in the input and read the result in the target transcript.

For local backups or diagnostics, these are the default roots. An absolute value for the corresponding XDG variable overrides each default.

Channels

A channel has its own history and workspace. Each agent resides in one channel and can subscribe to others. You reside in /inbox, also shown as home in the sidebar. Viewing or controlling another channel does not move you there. Typing ordinary text in the inbox starts no agent turn.

Common Lisp 
(open "inbox")
(tell "@researcher" "Check the release notes.")
(open "/researcher/reviewer")
(rename "/researcher/reviewer" "critic")

Use (open) to find a channel by handle, path or ID. Use the full ID in scripts if the name may change.

  • Type @researcher please check this to send a copy of a message to that participant.
  • Use (tell "ID" "text") to send a message directly.

Open (open "inbox") to read messages addressed to you. Use the link in a notice to jump to the source channel.
