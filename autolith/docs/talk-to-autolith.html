Talk to Autolith

Prose, Lisp, and commands

Type a request in plain text to send it to the current channel. For example, ask Autolith to review a change and name the file or test you want it to check. Type @ to complete a workspace path or a participant handle. A token that contains a slash is treated as a path.

Start input with ( to evaluate Common Lisp in the active image. Autolith passes the form and its result to the model. The form has its normal effects in that image. To send text from a file, or to attach an image, use channel.send:

Common Lisp 
(channel.send :text (read-file "request.org"))
(channel.send :channel "@test-review" :text "Run the focused tests.")
(channel.send :text "Review this diagram" :images #("/tmp/diagram.png"))
  • Run (help) for an overview or (help :commands) for the command list.
  • Use a keyword for a topic, as in (help :conversations). Use a quoted command or a tool name for its arguments, as in (help 'open) or (help "lisp.eval"). Browse a namespace with (help :lisp) or use (help :all) for the full reference.
  • Press Tab after =(help = to complete a topic or operation. For command options, press Tab after a command name and a space. For example, complete (ste t) to request Simple Technical English and (ste nil) to turn it off.

Use ? followed by whitespace to evaluate one Lisp form in the background. This also works for a bare variable. Input such as ?text or ?? is plain text.

Common Lisp 
? *package*
? (progn (sleep 10) (values :finished 42))

Use the printed exec:N ID to inspect, wait for, or cancel that job: (job.get :id "exec:1"), (job.wait :id "exec:1"), or (job.cancel :id "exec:1"). Replace exec:1 with the ID you received. In fullscreen, click the printed cancellation form to insert it in the composer. The result and captured output go to the original conversation even if you switch channels. Background Lisp uses EOF for input and reports errors without an interactive restart picker. Submitting a form this way does not start a model turn.

When local Lisp or a command fails and the restart picker opens, choose Ask Autolith why this failed to diagnose it while the operation is suspended. Review the proposed recovery before choosing a restart or retry. A retry does not undo effects that happened before the error. Escape during diagnosis returns to the picker; Escape at the picker aborts the failed operation.

During a model turn, Escape cancels that turn and lets queued steering proceed. Ctrl-C cancels the turn and pauses queued work until your next submission. A second Ctrl-C within the force-exit window exits the application. Use (cwd) to see the current workspace. If you submit (cwd "../other-project") during a turn, the relative path is resolved when that input reaches its place in the steering queue.

Parking and editing queued input

  1. Run (vault-store) to park queued work and unconsumed steering. Work already in progress continues.
  2. Run (vault-contents) to inspect the parked entries in restoration order. Entries are zero-indexed. Use setf to publish a change.
  3. Run (vault-restore) to put the edited entries at the front of the live queue.
Common Lisp 
(vault-store)
(vault-contents)
(setf (vault-contents 0) '(:message "Run the unit tests first."))
(vault-restore)

Use (vault) for a summary. To replace the entire list, set (vault-contents) without an index. Its entries may be (:message INPUT), (:command TEXT), (:lisp SOURCE) or, for scheduled wakeups, (:native-lisp SOURCE). Set the list to nil to clear it.

Managed resources

Use resource.read to read a file or another resource. For an edit, pass the revision from that read as :base-revision to resource.edit. If the resource changed, read it again before editing. For a multi-file cl-resources change, Autolith checks every staged revision before publishing. If publication fails partway through, Autolith restores the earlier files unless an external change requires manual recovery.

Common Lisp 
(resource.read :uri "workspace:README.md")
(resource.read :uri "channel:current" :query "unit tests" :max-results 5)
(resource.read :uri "channel:current" :start-sequence 120 :record-count 10)
Resource Use
channel:current Read recent history, including records from before compaction.
channel:id/ID Read the history of one other channel.
channel:list Find channels and their participants. Reading does not subscribe you.
papercut:current List active reports about the running Autolith harness or its tools.
papercut:id/ID Read one papercut. Percent-encode the stable ID if necessary.

History searches are limited to one channel and match all the search terms. Page by sequence number or read a long record on its own. Use (papercuts) to list reports, (papercut "ID") to inspect one, or (papercut-close "ID") to close it. Agents can report a harness defect with papercut.report or assess and close a report through its resource where authorized. Put project bugs and test failures in the plan or agenda rather than the harness reports.

Memories

Use a note for a preference or convention and a fact for a value you want to reuse with its evidence. An agent can edit its own notes through memory:personal. That scope follows the agent across channels and restarts. Top-level agents can also write shared workspace and global memories. Their children can read those shared memories.

Common Lisp 
(memories)
(memories "deploy")
(memory "3afbfa1a")
(forget "3afbfa1a")

In fullscreen, (memories) opens the memory manager. Press / to search, Tab to choose between All, Notes, and Facts, and Shift-Tab to choose a scope. Press Enter to read the selected item on a narrow terminal. Use n to create a note, e to edit it, d to forget it or retract an asserted fact, and r to reload. In the note form, use Tab to move between fields, Space to choose a scope, Shift-Enter for a newline, and Enter to save. Outside fullscreen, the listing and explanation commands print text. Use a full ID or a unique ID prefix.

A note can cite a file, a web page, your words, or another memory as a premise. A note is stale if a cited passage disappears from a file or a premise changes. Any notes derived from it become stale too. A note whose only cited files cannot be read is unverified. Inspect the evidence with (memory "ID"). Update the source or premise when you update what the note claims. Retagging a note does not refresh its evidence.

For agent-written notes, the memory-remember and memory-replace operations accept sources and premises. Use memory:id/ID to inspect one note. Workspace file references inside that workspace are relative and can move with an export.

Facts and rules

A fact records a typed value and what supports it. For instance, the assertion event.start review 2026-10-22T13:00:00Z can come from your message or a calendar file. The two sources are kept separately. A derived fact keeps the basis of its premises: a calculation based on an assumption is still an assumption.

For an example, ask the agent to use the appointments recipe:

  1. Give it the start time of the review, 30 minutes of travel, and a 10-minute buffer.
  2. Admit the proposed departure rule. Run (rules) to get its name or ID.
  3. Change the start from 13:00 to 13:15. The derived departure changes from 12:20 to 12:35 without another model request to run the rule. Run (what-changed) to see the change and its cause.
Common Lisp 
(rules)
(admit-rule "departure")
(what-changed)
(why "c4dfffae")
(retire-rule "departure")

Use (why "ID") to inspect the sources, rule and premises of a fact, or the evidence for a note. Use (forget "ID") to retract an asserted fact. If two facts disagree, both are shown as conflicted. A negated premise requires an explicit negative fact; missing information is unknown. Recheck evidence when a cited file changes. Web evidence expires after a week and tool output after a day; observe it again to renew it.

Agents can inspect memory:facts, memory:claim/ID, memory:predicates, memory:rules and memory:changes. The memory:recipes resource lists appointments and service-dependencies. Use recipe-use on memory:facts to define the predicates and propose the rules. The same resource accepts predicate-define, fact-assert, fact-retract, and rule-propose.

Set knowledge-mode in (settings) or through AUTOLITH_KNOWLEDGE. Use active to record and recall knowledge, passive to record without giving facts to the model, or off to stop recording. The default is active. To inspect how much of the current conversation was spent on structured knowledge, use:

Common Lisp 
(knowledge-usage-report (application-conversation *active-application*))

Plans, methods, gates, and contracts

Use facts when a plan or action depends on something you can check. For the review example, a plan step can say Leave at {?leave} and require event.departure review ?leave. Before the departure is known, the step is blocked. When the time changes, the displayed step follows it. A completed step is flagged if its recorded facts later stop holding.

  • A method describes how to do a task under stated conditions. Ask the agent to run plan.expand to expand a task into ordered steps. Inspect definitions in memory:methods.

  • A fact gate checks a mission against accepted evidence. By default it requires an undisputed observation or a statement from you. For example:

    Common Lisp 
    (:id "departure-known" :kind :fact :pattern ("event.departure" "review" "?t"))

  • A tool contract can require facts before a call and record facts from its result. For example, require a verified destination before publishing a report. If the prerequisite fails, the tool is not called. A predicted effect only counts if the contract explicitly accepts it.

Agents propose methods and contracts with method-define and contract-define on memory:facts. Inspect contracts in memory:contracts. Review the complete contract.admit request before enabling a new version. Imported contracts also need local approval. A tool result marked externalSuccess: true and contractRecording: "failed" means the action succeeded and only the evidence recording failed. Check the result before retrying. If damaged contracts block ordinary calls, ask the agent to call contracts.reset. This archives the original log and clears all contracts and saved diagnoses without clearing facts or notes.

Learned procedures

When three successful turns in a workspace repeat a sequence of tool calls, Autolith can learn a procedure locally. For example, after repeated requests such as Make the sales report for q5., a notice may name make-sales-report and offer it for later requests with another file. Use (procedures) to see its calls, parameters, status and measured savings in model requests and tokens.

Common Lisp 
(procedures)
(admit-procedure "make-sales-report")
(run-procedure "make-sales-report" :file "q5")
(retire-procedure "make-sales-report")

Replace the name and parameters with those listed for your procedure. The first run normally asks you to admit the procedure, and its calls still follow tool approvals and contracts. An exact request pattern can run automatically once the admitted version has demonstrated savings on completed turns. An approximate match is only offered to the model. Two consecutive failed runs suspend the procedure; use (admit-procedure "NAME") after you check it. Use (retire-procedure "NAME") to prevent further runs and relearning. Agents inspect procedures at memory:procedures and invoke them with procedure.run. Learning and recall require active structured knowledge.

Diagnosis

Ask Autolith to diagnose a failure when more than one cause fits. With structured knowledge active, the agent can use diagnosis.run to compare up to four hypotheses with existing facts and up to three tool probes. Each probe needs a contract that records what the result establishes. An observation can rule out a cause; missing evidence leaves the case open.

For example, if a report fails to reach a service, check whether the service is reachable and whether the configured endpoint is current. A successful reachability probe rules out an outage; a stale endpoint gives you a specific setting to fix. Use (diagnoses) to review the evidence and saved diagnoses. Disable probes in (settings) or with AUTOLITH_DIAGNOSIS=0.

Exporting and importing data

Export a workspace from the OS shell, then import it at its new path:

Shell 
autolith data export project.sexp --workspace /home/al/code/project
autolith data import project.sexp --workspace /home/al/src/project

Use the same archive format at the Autolith prompt:

Common Lisp 
(data.export "project.sexp" :workspace "/home/al/code/project")
(data.import "project.sexp" :workspace "/home/al/src/project")

Export includes conversations, notes, facts, rules, agendas, plans, papercuts and related assets. Copy the repository separately. Credentials, configuration, images and caches are excluded. Omit --workspace to export all workspaces and global data, or pass --all explicitly (:all t in Lisp).

Pick a new filename for export. Import merges data by stable ID, skips identical records and stops before publication on an ID conflict. Use --workspace on import to relocate a single-workspace archive. Without it, the original paths are preserved. Run autolith data export --help or autolith data import --help for options. CLI exit codes are 0 for success, 64 for invalid arguments and 1 for a transfer failure.

Session titles and resume

A channel gets a local title from your first prompt or image. Autolith can ask the model to refine the title after the third user turn and name the agent after three user turns or 25 tool calls. Use (rename "NAME") to name the current agent yourself. That name takes precedence over automatic naming. Inspect or change the setting with (settings :session-title-generation-p) or (settings :session-title-generation-p nil).

  • Run (channel-id) to find the stable ID of the current channel.
  • Run (open) to pick a channel or (open "ID") to open it directly.
  • Run (delete) to remove the displayed channel, or (delete "ID") to choose another. Confirm only if you intend to remove its history and child channels. The subtree must be idle and free of other attached clients.

Reopening a live channel gives you its jobs and history. If Autolith needs to serve the conversation in a new process, the history is available, but old background jobs and Lisp worker state are gone. Durable child task results can still be read with job.get.

Usage

Run (status) or its alias (usage) at the Autolith prompt for model usage:

  • Token usage sums recorded input and output for this conversation. The prompt-cache row shows cache usage when reported by the provider.
  • Context is the current space used in the model window, not the sum of tokens sent over the conversation.
  • Cost covers recorded requests in this process. Review any unpriced request count before treating the total as a bill. Subscription rate limits are shown when available.

From the OS shell, run autolith usage for stored conversation and knowledge counts, logical disk usage, and resident memory (RSS) of reachable processes. The disk total counts overlapping roots and hard links only once. RSS can count shared pages once per process. Run autolith status instead to inspect running channels and the server. Set NO_COLOR for plain output in a terminal.

Local sessions

Starting and switching channels

An interactive autolith launch starts the background server if needed and serves the inbox. Use the following shell commands to work on a channel:

Shell 
autolith open
autolith open researcher --read-only
autolith open /researcher/reviewer
autolith new /home/al/code/project
autolith new /home/al/code/project --detached

Without a target, autolith open opens the last changed top-level channel in the current workspace or creates one if there is none. Use autolith new for a fresh channel; add -d or --detached to create it without attaching. To open it later, use the printed autolith open ID command. Only one terminal can control a channel. Use --read-only to observe from another terminal.

Inside Autolith, use (open "ID") to switch channels. Use (detach) or Ctrl-Z to disconnect the terminal and leave work running. Use (exit) to end the channel. To stop all channels and their server, use autolith stop from the OS shell or (stop-server) from Autolith. Updating or rolling back also stops the shared server.

An idle channel can unload after (config :channel-idle-minutes) minutes (30 by default) if nothing is running or queued and no terminal shows it. Open it again or send its agent a message to serve it again. If you pipe a script into autolith or autolith open ID, submissions run in order and the transcript goes to standard output. A script cannot answer interactive approvals. The channel closes when input ends.

Checkpoints and launch options

Run (checkpoint) to save the shared process. Work already in progress finishes first, across all channels. New turns wait until after the save. Terminals reconnect automatically, and the requesting channel receives the generation ID. On Windows, the launcher restarts the server from the saved heap.

If you lose a connection unexpectedly, press r or Enter to retry the same channel, enter an ID to switch, or press q to detach. Retrying does not resubmit your work.

Use --model, --permissions or --immutable when creating a channel. Pair --provider with --model. When opening an existing channel, the only launch override you can pass is --permissions, and only when no terminal controls it. To choose a permission mode in the channel, run (permissions).

Channel sidebar

In fullscreen, unfold home to find channels grouped by repository or workspace. Linked worktrees share a group when Autolith can identify their originating checkout. Independent clones have separate groups. Child channels are nested under their parent. Home shows the inbox and its unread count.

  • Press Ctrl-S to toggle the sidebar. On a narrow terminal it opens as a drawer.
  • Click the sidebar or press Ctrl-Space (Ctrl-Tab where supported) to focus it. Use the arrows to select or expand an entry, Enter to open it, or Delete to remove it after confirmation.
  • Type to filter by agent name, ID, title or workspace. Press Escape to clear the filter or return focus to the transcript.
Marker Meaning
▌ Current channel in this terminal
▸ / ▾ Closed or open group
● / ○ Agent working or hosted but idle
· / ? No running session or unknown status

A yellow number counts messages received since this terminal last viewed the channel. @ counts mentions, and N pending counts deliveries waiting for a channel that is not loaded.

Session endpoints

Run autolith status to list live sessions or autolith status --sexp for use in Lisp scripts. The controlling terminal has its own PID, distinct from the server PID. In the S-expression, use :terminal-client-pid for the controller, :observer-client-pids for read-only clients and :pid for the host.

Shell 
autolith start
autolith tell researcher 'Review the failing unit test.'
autolith tell /researcher/reviewer '(channel-id)'
autolith pause researcher
autolith detach researcher

Use start to launch the server in the background, tell to submit input, pause to cancel active work and hold queued work, or detach to disconnect the client. You may omit the target from pause and detach when exactly one endpoint is reachable. Use tell for an unloaded channel too. Its agent is started without a terminal.

A message beginning with ( is evaluated as Lisp in the target. Supply all arguments and read the result or error in the target transcript. The shell command acknowledges routing and does not wait for the result. Interactive pickers and confirmations are unavailable through autolith tell.

For local backups or diagnostics, these are the default roots. An absolute value for the corresponding XDG variable overrides each default.

Purpose XDG variable POSIX default Windows default
Configuration XDG_CONFIG_HOME ~/.config/autolith/ %APPDATA%\autolith\
Durable data XDG_DATA_HOME ~/.local/share/autolith/ %LOCALAPPDATA%\autolith\data\
Process state XDG_STATE_HOME ~/.local/state/autolith/ %LOCALAPPDATA%\autolith\state\
Cache XDG_CACHE_HOME ~/.cache/autolith/ %LOCALAPPDATA%\autolith\cache\

Endpoint records, leases and recovery state are under the state root. The management REPL socket defaults to management/repl.sock there on platforms with filesystem sockets. Channel clients use private authenticated loopback connections.

Channels

A channel has its own history and workspace. Each agent resides in one channel and can subscribe to others. You reside in /inbox, also shown as home in the sidebar. Viewing or controlling another channel does not move you there. Typing ordinary text in the inbox starts no agent turn.

Common Lisp 
(open "inbox")
(tell "@researcher" "Check the release notes.")
(open "/researcher/reviewer")
(rename "/researcher/reviewer" "critic")

Address a channel by agent handle, exact path, full ID or unique ID fragment. For autolith open, a bare agent name works too. Use a full ID in a bookmark or script if the names may change. A path follows channel ancestry and can change when an agent is renamed. Copy the displayed path, including case and percent escapes. Find paths with (open) or channel:list. Use (tell) to pick a recipient and prepare a message. Use (rename "WHO" "NAME") to rename a participant. Handles accept letters, digits, hyphens and underscores and are matched without regard to case.

Use a mention such as @researcher please check this to send a copy to a participant from your current conversation. A mention starts a word, so the @ inside a mail address does not count. To send directly, use (tell "ID" "text"). Agents use channel.send and can follow other channels through channel.subscribe and channel.unsubscribe. Subscribers receive copies of messages and replies. An agent can use @parent to reach its nearest active ancestor or, if there is none, you.

An idle agent starts work when it receives a message. A working agent receives it as steering. Messages for you go to the inbox. Open it with (open "inbox") and use the open form at the end of a notice to jump to its source. Read a child agent transcript at channel:id/ID, where ID is its execution ID. Child channels nest under the parent; AUTOLITH_TASK_MAX_DEPTH defaults to three levels below a top-level agent.
