Docs · Configure Autolith

Development guide. For Autolith 0.67.66, see the release guide.

Configure Autolith

Put personal configuration in ${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp. This file runs as Common Lisp in the AUTOLITH package with your privileges. Use --pristine to skip private replay and executable initialization.

After the tracked code and selected private image have loaded, Autolith loads these files in order:

  1. The site init.lisp, if a site root is configured.
  2. Trusted .autolith/init.lisp files, from the outermost directory to the nearest one.
  3. Your personal init.lisp.

This order also applies to autolith models and autolith auth. Your personal file reloads if you reconnect to a retained generation. Startup or reload reports the pathname if a configuration file cannot be read or evaluated.

Packagers can set a read-only site root with --site-config-root DIRECTORY or AUTOLITH_SITE_CONFIG_ROOT. Use an existing absolute directory. It can contain init.lisp, mcp.sexp, skills/ and agents/. A site init.lisp runs with the same privileges as personal configuration. Use an explicit site root in place of XDG_CONFIG_DIRS.

Settings

Use (settings) to open the settings picker. Select a setting to see the current value, where it came from, and the available choices. In a script, (settings) prints the settings by area.

You can use the same command without the picker:

  • (settings :boot-screen-seconds) describes the setting.
  • (settings :boot-screen-seconds 2) sets the value.
  • Use t or nil for switches. Omit the value if you only want to inspect the setting. An explicit nil counts as a value.

Settings have four scopes:

  • Durable. Your model, reasoning effort, reasoning traces, timestamps and saved permission mode belong to this scope. Changes are saved immediately in preferences.sexp under the configuration directory.
  • Session. Settings such as hurry-up mode last until exit.
  • Process. Startup sets the configuration roots and management endpoint.
  • Derived. The provider endpoint and context window depend on the model. For the context window, Autolith tries the declared value first, then the catalog value, then the default.

For durable settings, the first available source wins:

  1. An explicit command-line option.
  2. The environment variable for the setting.
  3. The saved value in preferences.sexp.

If a saved provider or model is unavailable, Autolith uses a registered choice and shows a notice. Register the provider again to recover the saved choice at next startup. Invalid command-line or environment choices produce an error. Use --model or AUTOLITH_MODEL to select a model served by the provider.

In Lisp, read settings with (config :model) or pass an explicit configuration with (config :model configuration). Change the current value with (setf (config :reasoning-traces-p) t). Use configuration-copy to make a separate configuration.

Upgrading from preferences versions 1 through 7: Run Autolith 0.53 once to write version 8 before you upgrade to 0.54 or later.

Language servers

  1. Install a language server that you trust. It runs with your privileges and inherits your environment.
  2. Create lsp.sexp in your user configuration directory, beside init.lisp. Here is a configuration for clangd:
Common Lisp 
(:version 1
 :servers ((:name "clangd"
            :command "clangd"
            :arguments ("--background-index")
            :extensions (".c" ".h")
            :language-id "c"
            :root-markers ("compile_commands.json" ".git")
            :timeout-seconds 30)))

For each server, provide a unique :name, a :command on PATH, a nonempty :extensions list and a :language-id. Use literal strings for arguments.

  • Use JSON object strings for :initialization-options and :settings.
  • Set :disabled-p t to disable an entry.
  • The request timeout defaults to 30 seconds. You can set it to an integer from 1 through 120.

Autolith reads LSP configuration from your user configuration directory.

Configure at least one enabled server to use the lsp tools. If the file is malformed, run lsp.status to inspect the configuration error.

Ask Autolith to use these tools:

  • lsp.status: inspect configuration and running project/server pairs.
  • lsp.query: request definition, references, hover, implementation, type-definition, document-symbols, or workspace-symbols for a workspace file. Position queries require one-based line and character coordinates, with columns measured in UTF-16 code units. For workspace symbols, supply query; the file selects the project and server.
  • lsp.diagnostics: synchronize a file and retrieve diagnostics.
  • lsp.restart: stop servers and reload the configuration after changing it.

Use lsp.semantic for revisioned transformations:

  • prepare-rename: inspect the symbol at path, line and character.
  • rename: propose a symbol rename with those coordinates and new-name.
  • code-actions: discover choices for a range, using line, character, end-line and end-character. Optionally filter only action kinds or supply diagnostics.
  • resolve: retrieve a complete action using its returned choice ID.
  • propose: retain an action's edit as an applicable proposal using choice.
  • move: propose server preparatory edits followed by moving path to new-path. Both paths must identify regular files or a missing destination.
  • inspect: review a retained proposal ID.
  • apply: apply a retained proposal. Obtain explicit approval for annotations with needsConfirmation, then include their IDs in approved-annotations. Confirm each synthetic lsp.semantic-confirmation request through the ordinary command-permission prompt. Without a permission callback, confirmation is denied.

Use local file:/// URIs for regular files. Before you apply a proposal, Autolith checks permissions, file revisions and synchronized versions. Request a new proposal after a conflicting edit or server restart. Server commands are returned as data for separate approval and execution.

Autolith starts servers on demand. It uses the nearest configured root marker inside the workspace, or the workspace itself if no marker matches. All enabled servers that match the file suffix receive the request. Open files are refreshed from disk first.

Diagnostics. Ranges are zero-based and measured in UTF-16 code units. The sources field gives the freshness of push and pull results. The diagnostic state means:

  • received: The report is versioned.
  • unversioned: The snapshot of the file could not be confirmed.
  • pending: No report arrived.

The automatic check after resource.edit shares a one-second deadline across all matching servers. If it times out, use lsp.diagnostics to allow two seconds for push reports and the configured timeout for pull requests. Use lsp.restart to release the servers.

Active-image management endpoint

The management REPL is an always-enabled endpoint for evaluating Common Lisp in the running AUTOLITH image. Use eval-connect and eval-call from image-daemon to connect from Lisp.

Put a nonempty token in a regular file owned by your user with mode 0600. Connections use HMAC-SHA-256 and a fresh nonce. The token itself is read from the file during authentication and is not sent over the connection.

The following environment variables configure newly created applications:

Variable Default Meaning
AUTOLITH_MANAGEMENT_REPL_TRANSPORT unix, or tcp on Windows unix or tcp.
AUTOLITH_MANAGEMENT_REPL_UNIX_SOCKET ${XDG_STATE_HOME:-~/.local/state}/autolith/management/repl.sock Unix socket pathname.
AUTOLITH_MANAGEMENT_REPL_TCP_ADDRESS 127.0.0.1 IPv4 loopback listener address.
AUTOLITH_MANAGEMENT_REPL_TCP_PORT 4141 TCP listener port.
AUTOLITH_MANAGEMENT_REPL_TOKEN_FILE ${XDG_CONFIG_HOME:-~/.config}/autolith/management-repl.token Mode-0600 token file.

Evaluation and authentication deadlines are 10 seconds. Frames are bounded to 1 MiB, source and output to 256 KiB, and queued evaluations and clients to 64.

Trust boundary. TCP is restricted to IPv4 loopback and uses no TLS. Use trusted local clients. Evaluation results can contain secrets.

On Unix, Autolith uses a mode-0700 directory and a mode-0600 socket. Startup can replace a stale socket owned by the current user. On Windows, use TCP.

Wire protocol

Each message is a four-octet unsigned big-endian length followed by exactly that many UTF-8 octets containing one readable S-expression. Length zero, oversized or truncated frames, invalid UTF-8, malformed syntax, and trailing forms are rejected. Readers use standard I/O syntax, a fresh standard readtable, and *read-eval* nil.

The server starts each connection with:

Common Lisp 
(:challenge :version 1 :algorithm :hmac-sha-256 :nonce HEX)

HEX encodes 32 random nonce octets as 64 lowercase hexadecimal characters. The client reads its token file, computes HMAC-SHA-256(token, nonce), and replies:

Common Lisp 
(:authenticate :proof HEX)

A valid proof receives (:authenticated :version 1). A proof is valid only for that connection's nonce. Authentication failure closes the connection without a reusable credential or detailed oracle response.

After authentication, send one request at a time:

Common Lisp 
(:evaluate :source "(values (+ 20 22) *package*)")

Send one form per request. Autolith evaluates it in the AUTOLITH package and captures output. A successful response looks like this:

Common Lisp 
(:evaluation-result
 :status :ok
 :values ("42" "#<PACKAGE \"AUTOLITH\">")
 :values-truncated-p nil
 :output ""
 :output-truncated-p nil)

The :values list contains one string per return value. A condition response includes :condition-type and :report. A deadline returns :status :timeout. The connection can accept another request. The deadline is best effort because trusted forms can suppress interrupts.

Autolith stops the endpoint before a checkpoint and restarts it afterward. If the evaluator cannot stop within two seconds, the checkpoint fails with management-repl-error and operation :quiesce.

Context

Use ephemeral notes to add temporary information to provider requests without adding conversation messages. For example, register advice for release requests:

Common Lisp 
(define-context-contributor release-advice (request)
  "Add advice for release requests."
  (when (search "release" (or (request-context-latest-user-text request) "")
                :test #'char-equal)
    (make-context-contribution
     :identifier  "release-check"
     :instruction "Verify release artifacts before publishing."
     :lifetime    ':turn
     :priority    40)))
  • A contributor receives a read-only request snapshot.
  • It can return zero, one, or many contributions.
  • Notes stack unless they deduplicate, supersede, or conflict.
  • Priority matters only when the advice budget is full.

Inspect contributions with (context). They apply only to provider requests; they do not count as conversation turns or attach to your messages.

Register selective project or user advice as a declarative rule:

Common Lisp 
(register-context-rule
 '(:id "lisp-edits"
   :when (:paths ("src/") :languages ("common-lisp")
          :events ("tool-success"))
   :instruction "Check the changed declarations before committing."
   :priority 30 :lifetime :while-relevant))

Use :paths, :languages, :tools, :namespaces, :roles, :diagnostics, :events and :output-contains in :when. Fields are conjunctive; values within a field are alternatives. Paths match prefixes; :output-contains matches literal case-insensitive substrings of recent completed assistant text and generated tool arguments. Other values match exactly. Add an absolute :workspace directory for project scope. Authorized tool operations and structured LSP severities supply bounded current-turn metadata. Asynchronous completions use their originating turn identity. Rules share the ordinary advice budget, priority, lifetime and deduplication policy. Inspect delivery with context-status; remove a registered rule with unregister-context-rule and its original ID.

To turn a complaint into a persistent correction, use:

Common Lisp 
(complain "Your explanations are too long. Give the result first.")
(wtf "Use the existing library instead of reimplementing it.")

Both names open the same interactive review. Inspect the generated instruction and literal trigger, amend the candidate, then choose workspace or global scope to save it. Saving an unmatched trigger and replacing an existing rule each require separate confirmation. Cancel to discard the candidate. Omit the text to enter a complaint in the editor.

Generation uses bounded recent assistant output and tool arguments as evidence. On later provider requests, matching corrections enter the ordinary request-local advice budget. Inspect them with (context). Global corrections are stored in data-root/context-rules.sexp; workspace collections live under data-root/context-rules/, keyed by the canonical workspace directory. A same-ID workspace correction overrides the global one in that workspace. Saves take effect on the next request, including in other sessions using the same data root. Edit or remove the data files to change saved collections.

The status line keeps a context meter visible while idle. It shows used tokens and the full model window. | marks the automatic compaction point. The ChatGPT subscription catalog currently reports a 272K-token window for the GPT-6.1, GPT-6, and GPT-5.6 models, which compact at about 218K tokens by default:

Code 
ctx [==========|..] 218K / 272K used

Before provider usage is available, the count uses four characters per token from the known system prompt, request-local guidance, retained conversation, and tool schemas. After compaction it estimates the replacement context until next provider report. Compaction request usage is recorded separately as work spent on the checkpoint.

If you switch Responses models, the new model receives the conversation and tool exchanges. Encrypted reasoning is available again if you return to the model that produced it.

Compaction

Use (compact) to make a checkpoint now. If a turn is active, compaction waits in the idle queue. Automatic compaction uses the same typed checkpoint format. Models from different providers can read the checkpoint. Earlier provider-native windows can still be read by the providers that made them.

A checkpoint records the current goal, decisions, constraints, completed and open work, uncertainties, and the next step. Recent turns are kept verbatim, normally up to two user turns and 32,768 characters. The latest user message and required tool or reasoning groups can exceed that bound. Live job state, mission policy and the current plan are read separately from their stores.

Evidence. Checkpoint notes can cite messages, tool results, plan steps, mission gates, symbolic facts and unfinished jobs. A completed note without a citation is marked (unsubstantiated). Use the channel:id/<id> address and record sequence to find a message or result. Use memory:claim/<id> to inspect a fact. After compaction, the next turn reports changes to cited steps, gates and facts. For example, a gate can become stale after an input changes.

If the model submits an invalid checkpoint, Autolith asks for a correction. After four unsuccessful attempts, it keeps the earlier checkpoint notes and recent turns. It records the range of history that was not summarized. If the provider is unreachable or refuses, or a permission check fails, the conversation is left unchanged.

A failed checkpoint writes a private report under compaction-reports/ in the state directory. It contains the error and last completed response, with active credentials redacted. In the terminal, use (copy bug report to clipboard) to copy the report.

Output limits and admission

  • (settings :max-output-tokens 4096) caps ordinary model replies. You can also set AUTOLITH_MAX_OUTPUT_TOKENS. Use nil, or the text none, off or unset, to use the provider limit.
  • (settings :context-output-reserve 8192) reserves at least 8,192 tokens for the reply. You can also set AUTOLITH_CONTEXT_OUTPUT_RESERVE. A larger explicit generation cap takes precedence.

Before sending a request, Autolith checks that the encoded prompt, tools and reply reserve fit within the model window. Cached input counts in full. The most recent compatible provider measurement is used if available. Otherwise Autolith estimates the input size locally.

Set ANALYTICS_EVENTS_FILE to export completed streaming calls as UTF-8 JSONL usage events. ANALYTICS_ACTOR overrides the operating-system username. Each schema-v1 llm-usage event contains the UTC timestamp, actor, model, request count, elapsed seconds, and known input, output, and cached token counts. Unknown token counts are omitted. Export is disabled without a destination. Appends are synchronous and serialized across processes; export errors do not abort a completed provider call.

Mechanical precompaction bounds oversized old tool output before a request, but only after an explicitly declared cache lifetime expires or the provider/model changes. A retention estimate alone never permits rewriting served history.

Excerpts include the head and tail, failure status, uncertainty about external effects, and a retrievable conversation/call reference. Calls, reasoning, and failed attempts are retained. Full outputs are available in the durable transcript; the latest user turn is untouched. Each precompaction is recorded and replayed on resume.

A same-provider/model resume preserves its prefix unless a known lifetime has elapsed. If a conversation has no recorded response identity, it is prepared once on resume. Manual, context-threshold, and scheduled idle compaction can still replace history with a summary, including when its cache lifetime is unknown.

Idle cache compaction is enabled by default. After a completed request with at least 32,768 prompt tokens and 131,072 characters of summarizable history, an idle session can compact two minutes before its estimated cache expiry. The timer starts when the request starts, not when its response finishes. User input, drafts, active work and shutdown take priority. Each opportunity is used once, including after failure. Resumed sessions need a new completed request before scheduling one.

Use (settings :idle-compaction-p nil) to disable it. The ChatGPT subscription route uses a conservative five-minute inactivity estimate. For Anthropic and OpenRouter Claude, the requested cache lifetime supplies the estimate. Other providers need an explicit estimate for idle compaction, for example (settings :prompt-cache-retention-seconds 1800) for thirty minutes. A positive value also declares a lifetime for precompaction; this is a user declaration, not evidence from the provider. Set it to zero to use the provider policy. Both settings persist across restarts. The ChatGPT estimate alone never permits idle precompaction; that route has no declared lifetime by default.

(settings :prompt-cache-ttl :1h) asks the Anthropic API and OpenRouter Claude models to keep cache entries for one hour instead of five minutes. A one-hour cache write costs twice the base input price, against 1.25 times for five minutes. The longer lifetime can avoid rewrites after pauses of five minutes to an hour; whether it saves money depends on reuse. Other routes ignore the setting. The requested lifetime supplies both the declared lifetime for precompaction and the estimate for idle compaction. An explicit :prompt-cache-retention-seconds setting takes precedence for both local policies. OpenRouter requests carry the conversation's cache key as their session identifier for upstream routing affinity from the first request.

Use (status) to inspect this process's model-request costs. Autolith uses reported charges when available, as with OpenRouter. Otherwise it uses a model-price snapshot: the built-in Anthropic API list prices, or (settings :model-prices "{\"model\": {\"input\": 2, \"cache_read\": 0.2, \"output\": 10}}") in US dollars per million tokens, keyed by the model name from (model). A missing cachewrite rate charges cache writes as input. Requests without a price, such as subscription routes, are counted as unpriced, not free. (settings :cost-limit 5) refuses new model requests, compaction and inference frames included, once reported and estimated spending reaches five dollars; zero disables the limit. Unpriced requests do not count toward it.

Cache retention depends on the provider, model, routing and account policy. The OpenAI API cache documentation describes a thirty-minute default for GPT-5.6 and later; it does not establish a retention contract for the ChatGPT subscription route. Idle compaction uses the ordinary paid checkpoint path. It can reduce the context sent after a long pause, but neither a cache hit nor a net saving is guaranteed.

Use (settings :cache-miss-notices-p t) to enable notices when cached reads fall by at least 128 tokens, including accumulated smaller losses. Notices also appear when cached reads remain flat while shared request history grows by at least 16,384 characters and at least one sixteenth of its reference size. Temporary context and newly offered history are excluded from shared growth.

A cache miss reports measured lost reads. A stall reports shared-history growth in characters because its token count is unknown. Both show cached and total input tokens and start with a red !. Model changes, idle intervals and smaller prompts are local observations, not proof of eviction or routing failure.

Each notice also identifies changes in the request as sent, compared with the previous request: top-level fields such as tools or system, the first item in the previous request's reusable prefix that the new request changes or omits, and moved cache markers.

The reusable prefix stops before temporary context and one-response exchanges, so appended history does not count as a change. If a request repeats the whole prefix, the notice reads prefix intact: the provider did not extend its cache. These comparisons use digests of the final request, not provider counters, and retain no prompt text.

The first request after resuming or compacting establishes a fresh baseline. Without comparable read counters or prefix measurements, no loss is inferred from total input. The setting is off by default and persists across restarts.

In Responses requests, skill catalogs and selected skill instructions keep their first surviving history position instead of moving after each new message. Autolith reads the current skill contents and checks activation on every request. Selected instructions expire with the logical turn; only the small selection call and result enter durable history. Mutable session state and other ordinary request context follow history. After compaction or removed history boundaries, Autolith places active skill context after the new history. Use (context) to inspect contribution sizes. Provider cache hits and savings depend on the provider and are not guaranteed.

Providers

Run a local model

Register local inference servers through the OpenAI-compatible Chat Completions API. The server must support streaming and the model must support tool calls to use Autolith tools. For an Ollama server on the same machine:

  1. If Ollama is not already running, start it with ollama serve. In another terminal, download a model that supports tools:

    Shell 
    ollama pull qwen3:8b

  2. Add this form to ${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp:

    Common Lisp 
    (register-openai-compatible-provider
 :name                         "local-ollama"
 :endpoint                     "http://127.0.0.1:11434/v1/chat/completions"
 :models                       '("qwen3:8b")
 :api-key-environment-variable "AUTOLITH_OLLAMA_KEY"
 :stream-usage-p               nil)

  3. Set a nonempty key value and start Autolith. Autolith sends it as a bearer key. Local Ollama ignores it, so ollama is a placeholder, not a secret.

    Shell 
    export AUTOLITH_OLLAMA_KEY=ollama
autolith models | grep -Fx 'local-ollama/qwen3:8b'
autolith --provider local-ollama --model qwen3:8b

  4. Send a short prompt to check that replies stream. Ask Autolith to list the files in the current directory to check tool calls.

If Ollama runs on another host, 127.0.0.1 still refers to the machine that runs Autolith. To keep the remote server private, forward the port over SSH: ssh -N -L 11434:127.0.0.1:11434 HOST. Use a different local port if 11434 is already in use and change :endpoint to match.

Troubleshooting. If the model is unknown, check the exact ID with ollama list. If the server rejects stream_options, use :stream-usage-p nil as shown above. If the server runs out of context, increase the context limit on the server first. Then set :models to a list of model property lists, for example '((:name "qwen3:8b" :context-window 32768)) for a server configured with a 32,768-token window. The registration does not change the server limit. See the Ollama API reference for supported endpoints.

Add another OpenAI-compatible provider

Use the same registration form for a local or hosted service. Change these fields in init.lisp and restart Autolith:

  • Provider name: Set :name to a unique name for Autolith.
  • Endpoint: Set :endpoint to the full streaming Chat Completions URL, typically ending in /v1/chat/completions.
  • Models: Set :models to the IDs you want to use, :models-endpoint to the full model-list URL, or both. Use static IDs if you want to select a model on the first launch. Inside Autolith, use (models :provider "my-provider") to refresh the model list from the service.
  • Credentials: Set :api-key-environment-variable to the name of a variable that contains the service key, or run autolith auth my-provider to store the key privately. A nonempty environment value takes precedence. Replace my-provider with your registration name.

Optional :headers adds non-secret HTTP headers. If the server supports the streaming usage chunk, you can omit :stream-usage-p to request it.

For a different wire protocol, use the Lisp extension point register-provider with a factory that returns a model-provider. The Chat Completions helper always uses Chat Completions.

Select a model with (model "glm-5.3-flash" :provider "neuralwatt") or (model "neuralwatt/glm-5.3-flash"). Use (models :provider "neuralwatt") to refresh and list one provider, or (model nil :provider "neuralwatt") to filter the interactive picker. The picker and listings show the provider with each model, including identical IDs offered by different providers.

Bare model IDs use the existing registration precedence. Only a registered provider name introduces a provider prefix; catalog IDs containing slashes, such as hf:zai-org/GLM-5.3-Flash, are matched intact. If a catalog ID also looks like another provider's full ID, specify :provider to select its exact catalog ID. An explicit provider and a conflicting qualified prefix signal a selection error. The selected provider is saved with the model in preferences and conversation history, so reopening a session uses the same registration.

Select a model for one launch with --model MODEL. Use a provider-qualified ID, or pass --provider PROVIDER together with --model for an exact catalog ID. These options work before or after run-job and open:

Shell 
autolith --model my-provider/my-model
autolith --provider my-provider --model hf:custom/model
autolith open --model my-provider/my-model
autolith run-job --model my-provider/my-model --input job.sexp --output result.sexp

The launch selection takes precedence over environment variables, saved preferences, and a resumed conversation's model. It does not save a new default; use (model ...) to save a selection. Autolith loads executable initialization and the local provider catalog before validating the requested model, so providers registered in init.lisp are available. Startup does not fetch a remote catalog; use autolith models to list locally known IDs and (models) to refresh them.

Model catalogs and sign-in

Startup uses built-in model metadata and the last successful local catalog. It makes no catalog request. Use (models) to refresh the picker. For several built-in providers, Autolith reads public metadata from models.dev. Custom registrations use the discovery URL that you configure. Copilot and Nous use account-specific catalogs. Subscription clients list models that the transport supports, which can differ from the public API catalog.

Built-in ChatGPT subscriptions use browser OAuth with PKCE and a local callback on localhost:1455 or localhost:1457 by default. Use (auth "chatgpt" :device-code) or autolith auth chatgpt device to select the device-code flow instead. The browser authorization URL is always printed for manual use. Grok and Nous Research use browser device flows. Gemini uses Google installed-application OAuth with a local loopback callback. Use an API key for Anthropic, Fireworks, OpenCode, OpenRouter, Mistral, OpenAI API and custom OpenAI-compatible providers.

The direct Anthropic catalog includes claude-fable-5-2, claude-opus-5-5, claude-sonnet-5-5 and claude-haiku-5-5 with one-million-token context windows. For these models, reasoning-effort selects low, medium, high, xhigh or max through adaptive thinking. Haiku 5.5 price estimates use its reported prompt length: the lower tier applies through 100,000 input tokens.

Autolith retains dispatched Anthropic messages in memory across tool rounds, new user input and request-local context changes. New input and changed context follow the dispatched prefix. Requests use at most four cache breakpoints across system instructions, tools and messages. Changed headers, rewritten history, compaction and ephemeral exchanges start a fresh projection. For a specifically identified thinking prefix-binding HTTP 400, Autolith retries once with Anthropic's binding control. The conversation log stores up to 32 rejected signature digests. Later requests use the control only while a rejected block is present and the effective thinking mode supports it. See Anthropic's prefix checks and effort guide.

OpenCode Go and Zen have separate provider selections and catalogs. Use (auth "opencode-go") for Go and (auth "opencode-zen") for Zen. The old opencode provider name is an alias for Go; existing opencode/... model IDs, OPENCODE_API_KEY, and saved Go credentials keep their Go routing. Zen models use opencode-zen/... IDs and OPENCODE_ZEN_API_KEY or a separately saved key. Refresh with (models) to load each tier's context windows and available models.

Go uses https://opencode.ai/inference/go/openai/v1 and Zen uses https://opencode.ai/inference/openai/v1. Both use Chat Completions. To override Go's endpoints, set AUTOLITH_OPENCODE_PROVIDER_ENDPOINT and AUTOLITH_OPENCODE_MODELS_ENDPOINT. For Zen, set AUTOLITH_OPENCODE_ZEN_PROVIDER_ENDPOINT and AUTOLITH_OPENCODE_ZEN_MODELS_ENDPOINT. Chat endpoint overrides include /chat/completions; discovery endpoint overrides include /models.

For the official OpenAI API, choose openai-api during onboarding, run autolith auth openai-api, or use (auth "openai-api"). Paste your API key at the hidden prompt. Autolith stores it in its private credential store and loads the models available to that key from https://api.openai.com/v1/models. Requests use https://api.openai.com/v1/responses. No init.lisp registration is needed. The chatgpt provider uses a ChatGPT subscription instead.

Authenticate a GitHub Copilot subscription with autolith auth copilot or (auth "copilot"). Approve the displayed device code at GitHub. Credentials are stored in the private copilot-auth.sexp under the state root. Tokens renew automatically before expiry.

Login discovers tool-capable picker models and copilot/auto, and attempts to enable unconfigured picker models. Models are named copilot/<model-id> locally to avoid collisions with direct vendor subscriptions. Successful Copilot login selects Auto and saves it as the default, unless the current Copilot model is still available. Use (models) to refresh the catalog, then (model "copilot/auto") to select Auto on an existing installation, or launch with --model copilot/auto. Normal startup reads the last successful catalog without a network request.

Use Auto with Copilot Student or Free plans, which do not offer manual model selection. Each request resolves an account-authorized concrete model and uses its Chat Completions, Responses, or Messages protocol with a short-lived session token. Auto keeps the previous concrete model while it is available. Hidden named models are not offered as manual choices. For other plans, select an available named model with (model). Disabled picker models are excluded.

For GitHub Enterprise Cloud with data residency, set AUTOLITH_COPILOT_DOMAIN to your TENANT.ghe.com hostname during both login and subsequent launches. Tokens are pinned to that host and streams use the subscription-specific endpoint returned by Copilot. Chat Completions, Responses, and Anthropic Messages reuse the existing transports. This integration uses GitHub's internal Copilot endpoints, following pi and VS Code, so it may require updates when GitHub changes that service.

ChatGPT models use Codex's default context windows, currently 272,000 tokens, instead of public OpenAI API limits from models.dev. In (settings), toggle prefer-codex-context-window-p off to use public catalog limits, or evaluate (setf (config :prefer-codex-context-window-p) nil). This saved choice applies only to the built-in ChatGPT provider. Set AUTOLITH_PREFER_CODEX_CONTEXT_WINDOW=off to override it for one process. AUTOLITH_CONTEXT_WINDOW takes precedence over both sources. Compaction uses compaction-threshold-percent of the selected window, 80% by default. The requests of a compaction are checked against the model's catalog limit when that is larger than the selected window, since compacting is how a conversation gets back under it. This holds for every provider and for a window set through AUTOLITH_CONTEXT_WINDOW.

ChatGPT Codex Fast mode sends service_tier=priority when the active Codex model advertises Fast support. Fast responses count more heavily against plan usage; the exact rate is set by OpenAI per model and is not tracked here. The built-in GPT-6.1, GPT-6, and GPT-5.6 models support it. Set :codex-fast-mode-p with (settings). Other providers and unknown Codex models use the standard path. Set AUTOLITH_CODEX_FAST_MODE to on or off to override the saved choice for one process.

If a request fails before model generation begins, Autolith retries it up to six times with jittered delays.

Once reasoning or output has streamed, or the provider reports token exhaustion (length, max_output_tokens, or max_tokens), Autolith makes at most two retries: three generation attempts including the original. Token exhaustion before visible text uses the same limit.

Set autolith::*provider-maximum-streaming-retries* in init.lisp to change this retry count; zero disables these retries.

Every failed attempt is recorded next to its request number with the attempt count, elapsed seconds, whether output was received, and provider identifiers.

ChatGPT Codex uses standard Responses requests and native Responses compaction. Normal requests enable provider parallel tool calls. Autolith executes independent calls concurrently, then records their results in provider wire order. Calls requiring a provider round trip, exclusive tools, and calls sharing one mutable runtime execute in separate ordered waves.

GPT-5.4 and later Codex models use native Responses tool search. Autolith sends stable namespace names and descriptions up front, marks each function defer_loading=true, and declares a client-executed tool_search.

When the model searches, Autolith searches its own registry within the namespaces advertised in that request. It scores namespace names, tool names, and description words, then appends the tool_search_output as a durable provider item.

The expansion replays intact in every later request. This keeps those tools loaded and the prompt prefix cacheable. Other models and providers receive the complete eager tool array.

Authenticate Gemini with autolith auth gemini or (auth "gemini"). Autolith stores its Google OAuth credentials separately at gemini-auth.sexp under the state root. The provider uses the Gemini CLI Code Assist subscription service directly, including streaming text and thinking, tool calls, token usage, account onboarding, and managed companion projects. AUTOLITH_GEMINI_OAUTH_CLIENT_ID may replace the public installed-application client ID; AUTOLITH_GEMINI_OAUTH_CLIENT_SECRET supplies a client secret when a deployment requires one.

Commands

Put commands in ${XDG_CONFIG_HOME:-~/.config}/autolith/init.lisp or load a Lisp file from there. Autolith loads user initialization after tracked code on ordinary startup, including after updates. Use define-application-command to register the command and set its help, completion and dispatch policies.

Common Lisp 
(define-application-command my-version-command
    (:name              "my-version"
     :aliases           ("local-version")
     :argument          "[LABEL]"
     :description       "show a labeled local integration version"
     :tip               "shows the version supplied by init.lisp."
     :busy-behavior     :execute
     :terminal-behavior :shared
     :callable          t)
    (application &optional (label "integration"))
  (application-present application (format nil "~A 3" label))
  :continue)
  • Arguments: Callable handlers take ordinary Lisp lambda lists, including &key and supplied-p parameters. Missing interactive arguments open the restart debugger. Use supply-arguments to pass replacement Lisp values. Autolith rejects excess arguments before dispatch.
  • Busy behavior: Choose :inspect, :execute, :apply, :hold or :cancel. Use :execute to run immediately, :apply to change state at the next safe provider boundary, or :hold to wait for idle. Argument-free :inspect and :apply invocations can show state immediately.
  • Terminal behavior: Choose :shared, :exclusive or :exclusive-without-arguments to specify which calls need exclusive input. A modal picker that changes state under :inspect or :apply waits for idle. A picker under :execute can open during inference.
  • Fixed options: Use :static-options instead of :argument for one positional choice. Supply strings, keywords or (t nil) for a boolean choice. Autolith uses these values in help and completion.

Live definitions

Use self.define to add or replace a loaded Lisp definition. Qualify the symbol or set package to choose the reader package. Use qualified symbols with self.set when changing global bindings in other packages. Autolith restores package locks after installation, discard or replay.

Use self.eval to evaluate in the active image. In a world, that is the server image. Set target to client to evaluate in the controlling terminal or, if there is no eligible terminal, the most recently attached eligible structured client. The client must advertise Lisp evaluation. Client evaluations are not journaled and do not survive the client process.

Tracked source takes precedence. On startup, Autolith skips a private definition if the tracked definition changed, appeared or disappeared, or if ownership moved to another library. A startup notice groups skips by reason. The next self.commit omits skipped definitions. For older commits without this metadata, tracked overrides replay only on the source revision used to publish the lineage.

Reapply a skipped definition against the current source to keep it. Or run (fix-skipped-definitions) to give the model the private, old tracked and current tracked versions. By default it rebuilds overrides that are still needed and publishes the result with self.commit. An optional comment takes precedence over that policy. If a turn is active, the command waits for idle.

Common Lisp 
(fix-skipped-definitions "Drop all of these. They were temporary development experiments.")

Refinement

Use (refine) to inspect proposals. Record a local task assessment before promotion:

Common Lisp 
(refine :assess "PROPOSAL-ID" :revision 3 :verdict :passed
        :evidence "Evidence from a separate task")

Promote from session to project to global scope. Each step requires renewed evaluation and checks for intervening owner changes. If an operation was interrupted, use the recorded evidence to recover it explicitly. Replay does not repeat the operation.

Executable Skills

Use skill.load with the exact catalog name to load instructions for the current turn. Use resource.read on skill:NAME if you need the full catalog description.

  1. Put a data-only EXECUTABLE.sexp beside SKILL.md or SKILL.sexp. Declare the Skill and ASDF system versions, entrypoint, contracts, capabilities and exact host tool names.

    Common Lisp 
    (:skill-executable :format-version 1 :skill-version "1.0.0"
 :system "my-workflow" :system-version "1.0.0"
 :entrypoint ("MY-WORKFLOW" "RUN")
 :self-test ("MY-WORKFLOW" "SELF-TEST")
 :verify ("MY-WORKFLOW" "VERIFY")
 :capabilities ("workspace-read") :tools ("resource.read")
 :input (:type :object) :output (:type :object))

  2. Define the entrypoint with input &key context. Use &key context for self-test and verification functions. Use portable JSON values such as (:object ("status" "ready")) for input and output.

  3. Install the ASDF system in the worker environment or pass an authorized asd pathname. Call skill.invoke with contract-valid input:

    JSON 
    {"name":"my-workflow","input":{},
 "asd":".autolith/skills/my-workflow/my-workflow.asd","async":true}

Use skill.verify with name to run the self-test. Set entrypoint to verify to run the verification function instead. Both tools require explicit full-access code authorization and run in a fresh worker. A worker can call only the declared host tools that the originating agent may use. Autolith rechecks source, manifest and ASDF version before execution.

Use async: true for a managed job. Autolith validates the result against the output contract and retains up to 1 MiB of data with the executable identity.

Local text redaction

Use (redact text) in the user REPL. From lisp.eval or a scratchpad, use autolith:redact.

Common Lisp 
(redact "Alice Smith lives in Amsterdam.")
(redact text :language "en")

Read both return values: the redacted string and :ok on success, or nil and a failure status. Autolith processes long prose in pieces. If any piece fails, you get no partial result. Inference runs locally. Review the result before sharing it because model redaction does not guarantee anonymity.

Packaged installations include the model and ONNX Runtime. For source installations without packaged defaults, set AUTOLITH_DEFINGERPRINTER_LIBRARY to the absolute native library path. Pass absolute paths for :model-directory and :runtime-library.

Worker tool calls

Pass exact tool names in host-tools to lisp.eval or lisp.scratchpad-run. Inside the worker, call:

Common Lisp 
(autolith:worker-tool-call "resource.read" "{\"uri\":\"workspace:src/main.lisp\"}")
(autolith:worker-tool-context)

Read :success-p, :content, :code and :details from the result. The originating conversation, permissions and mission admission apply to every callback. Use a different REPL for nested worker calls. Omit host-tools if no callbacks are needed.

For example, pass these arguments to lisp.eval to return the content on success and the error code on failure:

JSON 
{"host-tools":["resource.read"],
 "forms":["(let ((result (autolith:worker-tool-call \"resource.read\" \"{\\\"uri\\\":\\\"workspace:README.org\\\"}\"))) (if (getf result :success-p) (getf result :content) (getf result :code)))"]}

An interrupted callback is recorded as unknown-outcome. Inspect the effects before repeating a call that can change state.

Structural code edits

Load the optional system and configure ast-grep before creating the registry:

Common Lisp 
(asdf:load-system "autolith/structural")
(setf autolith:*structural-program* "/path/to/ast-grep")
  1. Call structural.query with a workspace URI and revision you have read.
  2. Call structural.rewrite and inspect the preview.
  3. Publish with structural.apply. Proposals are single-use, owned by the conversation and subject to the same revision checks as resource edits.

For an existing registry, call structural-register-tools with :program. Ordinary executable and file authorization apply. To test the backend, set CLASTED_AST_GREP to the backend path and run (asdf:test-system "autolith/structural/tests").

Debug adapter sessions

Load autolith/debug before creating the registry. Configure an adapter in user initialization or pass it directly to debug.launch or debug.attach:

Common Lisp 
(asdf:load-system "autolith/debug")
(setf autolith:*debug-adapter-program* "/path/to/debug-adapter"
      autolith:*debug-adapter-arguments* nil)

For an existing registry, call debug-register-tools with :program and literal :arguments. Adapter execution, launch, attach and evaluation require exact full-access command approval. Authorize source and program paths as usual.

Use the returned session ID in the conversation that created it:

  • Set breakpoints with debug.breakpoints and drive execution with debug.continue, debug.pause and debug.step.
  • Inspect state with debug.threads, debug.stack, debug.scopes, debug.variables and debug.evaluate. Read queued events with debug.events and optionally pass count or wait-for.
  • Interrupt an operation with debug.cancel or end the session with debug.terminate. On timeout or cancellation, Autolith closes the adapter.

Run the optional checks with (asdf:test-system "autolith/debug/tests").

Child roles

Autolith looks for roles in this order:

  1. .autolith/agents/
  2. ${XDG_CONFIG_HOME:-~/.config}/autolith/agents/
  3. <site-config-root>/agents/
  4. Bundled roles.

The first match wins. If it is malformed, Autolith reports the error rather than looking for another copy. Define a role as one bounded UTF-8 *.sexp property list:

Common Lisp 
(:name             "reviewer"
 :description      "Review a change for regressions."
 :instructions     "Report concrete, evidence-backed findings."
 :tools            ("resource.read" "search.*")
 :spawns           nil
 :models           ("@parent")
 :reasoning-effort :high)
  • Require :name, :description and :instructions. The other keys are optional.
  • Use nil, :all or exact names and namespace patterns for :tools. A role cannot grant self.*, task.* or yield.*. Grant job.* for job inspection, waiting or cancellation. Children can only access their own jobs and those of their descendants.
  • Use nil, :all or a list of role names for :spawns. The task depth limit still applies.
  • Set :reasoning-effort to a supported effort. Omit it or use :auto for medium. Codex Fast mode is not inherited.

Use child.roles to see effective roles and child.spawn to start a task. Reuse a child by sending work to its channel. An agent can have up to 32 children. Read channel:current to see which are busy. Use child.rename to rename one, child.compact to summarize an idle child's history, or child.remove to delete an idle child and its descendants. Opening a child's channel uses the same role and tools as a delegated run.

Channel deletion validates the whole selection first. If storage cleanup fails after deletion, use the retry-cleanup restart or let the next server start or deletion retry the intent in channel-removals/. Deleted identities cannot be reopened from leftover history.

Completion-driven turns

Set completion-policy on asynchronous tools or child.spawn. The same policy applies if a synchronous call outlasts the blocking grace period. Batch items inherit the outer policy unless they specify their own.

  • continue is the default. In a primary terminal or ACP session, idle completions in a one-second window share one automatic turn. If a turn is busy, results arrive at the next safe request boundary.
  • With notify, results arrive on the next ordinary turn. Interfaces without an input controller also deliver results on ordinary turns.

Continue independent work while jobs run. Yield the turn if all you need is the results. An empty reply shows a yield notice that counts the unfinished jobs eligible to wake the conversation. Use job.get to inspect a result or job.wait if you need to wait explicitly.

A goal or mission waits for eligible job results before resuming automatic continuations. Only the conversation that owns the work gets a wakeup. Delivery receipts survive restart and compaction, so a notification can be restored without repeating the job. Cancellation, paused or terminal missions, and spent budgets can prevent automatic turns.

Task inspection and continuity

Use (tell "CHILD" "text") to steer a running child at its next safe boundary. Use job.continuity with action set to list or get to see which retained jobs are live, complete, recoverable or need a decision. Lists default to 20 records (maximum 100). Pass offset to page and read :total, :next-offset and :more-p from the result.

To recover interrupted work:

  1. Inspect the retained job and its effects. Use a visible job ID or durable execution ID in id.
  2. To permit a restart, the primary owner calls allow-restart with a safety rationale about repeating external effects and authorize: true. For a saved worker, use checkpoint with a compatible image, target repl and authorize: true.
  3. Use revive or abandon with the ID and authorize: true. Revival can reattach live work, start the saved worker or dispatch a new child from a retained safe shared-workspace task specification.

Autolith records the decision before dispatch and links the executions. If revival fails or is interrupted, inspect the uncertain outcome before trying again. Resuming a conversation shows the inventory without replaying work.

Isolated modifying tasks

Pass an isolation object to child.spawn to give the child a detached Git checkout. Omit it for a shared workspace. Use these fields:

  • baseline resolves to a commit. The default is HEAD.
  • dirtyPolicy defaults to reject. Use ignore to start from the committed baseline and exclude staged, unstaged and untracked source changes.
  • artifactKind defaults to patch. A patch includes committed and uncommitted tracked changes. Use commit-range for a clean checkout whose history descends from the baseline.

Stage new files before yielding. The terminal result identifies the artifact for integration, including on abort. If extraction fails, Autolith retains the checkout and reports :worktree-error.

Use child.worktree with an explicit action:

  • inspect reports provenance, touched paths and the artifact path. Use extract to retry extraction after repairing a checkout. Pass the terminal job or durable execution ID as id.
  • check checks patch applicability. Use apply to patch the clean target or commits to cherry-pick the range. Pass id and an explicit target.
  • conflicts shows unmerged paths. Use abort to abort an interrupted cherry-pick. Pass the target repository.
  • cleanup removes the owned checkout. Pass discardDirty: true to discard local changes. The secured artifact is separate from the checkout.
  • discover lists owned worktrees. Pass source to recover registration from Git markers. Use cleanup-orphan with the discovered worktree id and source to clean up after failed task publication.

The sandbox can write the isolated checkout and its Git administrative directories. Integration requires authorization for the target. Worktree isolation prevents accidental overlap. It does not confine hostile code.

The default pool admits eight concurrent children. Set AUTOLITH_TASK_MAX_CONCURRENCY to raise this up to 32. Set AUTOLITH_TASK_MAX_DEPTH to change the default depth of three below a primary agent. Child jobs have a one-hour wall-clock deadline by default. Set AUTOLITH_TASK_MAX_RUNTIME_MS to change it in milliseconds or use zero to disable it.

Reusable shell sessions

Pass session to shell.run to reuse a POSIX shell. Commands in one shell run serially and share variables, functions and the current directory. Pass directory to change the directory first. Autolith authorizes each command in its observed directory and captures separate logs for each invocation. Use description to label the live row.

  • Use shell.sessions to inspect live and dead shells.
  • Use shell.close to stop and forget a shell.
  • Use shell.reset to replace a shell after exit, timeout or cancellation, or after permissions, workspace or writable scopes change.

The runtime stops its shells and descendants on shutdown. Reset does not replay commands. Keep temporary storage outside writable workspace roots for sandboxed sessions. On Windows, or for an independent POSIX command, omit session. Use native PowerShell on Windows.

On Windows, add existing read-only tool directories with *win32-sandbox-read-roots*. Sandboxed commands run serially while the helper applies temporary access rules. Use local directories without reparse points or hard-linked files. Unsupported scopes or a missing helper cause the command to fail.

Retained command output

shell.run returns the exit status and capture details with a short preview. Pass separate-output: true to capture stdout and stderr separately. Read the shell-log: references from the result or from job inspection after a restart or compaction. You do not need to rerun the command.

Use resource.read with zero-based byte-offset and byte-count (default and maximum 4096). For a literal search, use query and optionally max-results. Continue at the returned offset. A search scans up to 1 MiB per page. The default is 20 excerpts and the maximum is 50. Text display replaces invalid UTF-8. The retained capture preserves the original bytes.

Autolith restricts captures to the owning conversation and authorized task descendants. Defaults are 64 MiB per stream and 1 GiB overall. If a stream exceeds its limit, the result marks the capture incomplete. Eligible captures can be pruned after seven days or under byte pressure. Live captures, pending results and captures that support active structured facts receive pruning protection.

Adjust *shell-log-capture-byte-limit*, *shell-log-retention-byte-limit* and *shell-log-retention-age* in trusted configuration. Session export collects task metadata independently of local log storage.
