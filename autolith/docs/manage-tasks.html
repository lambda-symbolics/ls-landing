Manage delegated tasks and jobs

Set up a child role

  1. Save a role as a *.sexp file under .autolith/agents/ for the project or beside init.lisp under agents/ for personal use:

    Common Lisp 
    (:name             "reviewer"
 :description      "Review a change for regressions."
 :instructions     "Report concrete, evidence-backed findings."
 :tools            ("resource.read" "search.*")
 :spawns           nil
 :models           ("@parent")
 :reasoning-effort :high)
  2. Use child.roles to check that you can select the role. Project roles take precedence over personal roles and site roles.
  3. Ask Autolith to delegate a task to the role, or use child.spawn.

Choose how to receive job results

  • Use completion-policy: continue to have Autolith pick up the result automatically in the terminal or ACP session. This is the default.
  • Use completion-policy: notify to see the result on your next turn.
  • Use job.get to inspect a job, or job.wait to wait for the result.

Recover an interrupted job

  1. Use job.continuity with action: list or action: get to inspect the job. Check what it did before you repeat it.
  2. If the job needs to run again, the primary owner must authorise the restart. Use allow-restart with a safety rationale, or checkpoint if you have a compatible saved worker image.
  3. Use revive to recover the job, or abandon to close it. Pass the job ID and authorize: true.

Delegate work in a separate Git checkout

  1. Pass isolation: {} to child.spawn to start from HEAD. Use baseline to specify a different commit. If you want to exclude pending changes, pass dirtyPolicy: ignore in the isolation options.
  2. Ask the child to stage new files before it yields so that they are included in the patch.
  3. Review the artifact from the job with child.worktree and action: inspect.
  4. Use action: check to check whether the patch applies. If it does, use action: apply to apply it to the clean target checkout.

Use worktrees to prevent accidental overlap between edits. A worktree does not isolate hostile code.

Reuse a shell

Pass a session name to shell.run to keep the working directory and variables between commands on POSIX systems. Use shell.reset to replace the shell after it exits and shell.close to stop it when you are done.

Read earlier command output

Copy the shell-log: reference from the result or from job inspection. Pass it to resource.read with query to search the output, or use byte-offset and byte-count to read a page.
