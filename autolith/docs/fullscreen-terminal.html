Fullscreen terminal

Autolith uses the ordinary inline terminal presentation by default. Opt into the application-owned fullscreen viewport for a session with:

Shell 
autolith --fullscreen

Save the preference for future launches at the Autolith prompt:

Common Lisp 
(preferences-set-fullscreen (application-configuration *active-application*) t)

The fullscreen viewport keeps the transcript scrollable and pins the composer to the bottom. Use PageUp and PageDown for page movement, Ctrl-PageUp and Ctrl-PageDown to jump between the user and assistant messages while skipping the reasoning and tool activity in between, Ctrl-Home and Ctrl-End for the oldest and newest transcript positions, and the mouse wheel for incremental scrolling. The --fullscreen command-line option enables it for one launch without changing the saved preference. Pass nil to preferences-set-fullscreen to return future launches to inline mode. Because the viewport owns the mouse, hold Shift while dragging to select text with the terminal emulator. Fullscreen history lives in the application rather than the terminal emulator's native scrollback.

For input with matching saved memories, a dim @ N relevant memories exist line appears below your message. Its count is the number offered to the model for that request. Each input gets one notice across tool calls and provider retries.

Input recall includes every user message, command, and Lisp submission in the conversation. Automatic messages and assistant output are excluded. On first use, the complete input-only sidecar is built from the conversation records; later submissions are appended to it. Resuming reads this sidecar instead of replaying archived transcript chunks.

Clicking a web address in the fullscreen transcript opens it in the default browser, and every fenced code block ends with a ⧉ copy label that copies the block's source. Copies go to the host clipboard through wl-clipboard, xclip or xsel, pbcopy, or the Windows clipboard, and the terminal also receives an OSC 52 request, so a terminal reached over SSH or a localgroup relay copies on your own machine. Web addresses in every mode are emitted as OSC 8 hyperlinks, which terminals open with their usual modifier-click.

Fullscreen startup presents a brief Lisp-machine boot screen with a centered tip and a rock mascot that adapts to short viewports, then the session banner and transcript above the composer. Mouse wheel scrolling also works through a controlling local-session attachment.

The boot screen then waits for Space or Enter before opening the listener, rotating the startup tip every ten seconds while it waits. Ctrl-C on the waiting boot screen halts the session. Turn the wait off for future launches with (setf (config :boot-screen-linger-p) nil) or for one launch with AUTOLITH_BOOT_LINGER=off, and change the rotation with (setf (config :boot-screen-tip-seconds) 30) or AUTOLITH_BOOT_TIP_SECONDS. The animation takes (config :boot-screen-seconds) in total, 3.5 by default and also set by AUTOLITH_BOOT_DURATION, shared evenly by its phases. Skip the boot screen entirely with (setf (config :boot-screen-p) nil) or AUTOLITH_BOOT_SCREEN=off; (settings) lists all four.

Almighty theme

Shell 
autolith --almighty

forces the fullscreen viewport and presents the Almighty Lisp theme from almightylisp.com: near-white text on the site's blue, yellow for everything emphasized, cyan for code and strings, and an ALMIGHTY LITH boot mark. Terminals that advertise true color through COLORTERM get the exact colors; others get the nearest indexed or basic ones. The theme sets the terminal's default colors only while the viewport is active and restores them on exit. Save it for future launches with (setf (config :terminal-theme) :almighty); :autolith restores the default presentation. Detached sessions carry the theme across handoff.
