Fullscreen terminal

The fullscreen transcript scrolls above the composer, modeline, and activity rows. The modeline shows LIVE if you are following the newest output. Otherwise, it shows which rows are visible.

  • Use PageUp and PageDown to scroll one page, or use the mouse wheel to scroll a few rows.
  • Use Ctrl-PageUp and Ctrl-PageDown to jump between user and assistant messages. The jump puts the end of the message above the composer, or puts the header at the top if the message is taller than the viewport.
  • Use Ctrl-Home and Ctrl-End to jump to the oldest and newest retained transcript positions.
  • In a hosted channel, press Ctrl-S to toggle the sidebar. Press Ctrl-Space to focus it. See Local sessions.
  • Drag across the transcript to copy selected text on release. Use Shift and drag to select whole screen rows in the terminal emulator instead.

Fullscreen history is separate from the terminal emulator's scrollback. The viewport keeps about four million characters of recent output in memory. At the oldest retained row, the modeline shows (history) loads earlier. Run (history) to load a page of older output.

When saved memories match your input, a dim @ N relevant memories exist line appears below your message. It shows how many memories were offered to the model for that request, followed by how many of them are stale or unverified (see the Memories section). Each input gets one notice across tool calls and provider retries.

Input recall includes every user message, command, and Lisp submission in the conversation. Automatic messages and assistant output are excluded. On first use, the complete input-only sidecar is built from the conversation records; later submissions are appended to it. Resuming reads this sidecar instead of replaying archived transcript chunks. If cache storage is unavailable, recall streams the conversation records directly. The editor keeps the newest 500 inputs, up to a million characters, in memory. Moving past the oldest of them loads the next older page, and leaving history recall releases it again.

Clicking a web address in the fullscreen transcript opens it in the default browser, and every fenced code block ends with a ⧉ copy label that copies the block's source. Copies go to the host clipboard through wl-clipboard, xclip or xsel, pbcopy, or the Windows clipboard, and the terminal also receives an OSC 52 request, so a terminal reached over SSH copies on your own machine. Web addresses in every mode are emitted as OSC 8 hyperlinks, which terminals open with their usual modifier-click.

Clicking a tool call's header in the fullscreen transcript inserts its Lisp invocation, such as (resource.read :uri "file:///tmp/notes.org"), into the composer at the cursor. Submitting it alone repeats the call with the same arguments; editing it first runs a similar call; writing around it asks the model about that exact call. Arrays are spelled as (vector ...) and objects as (dict ...), and argument names with uppercase letters keep their case as :|filePath| or a string key.

Click a lisp.eval input block in fullscreen to expand the complete Lisp source with syntax highlighting. Click it again to collapse it. The selected view persists through resizing and tool completion.

Lisp evaluation inputs, returned source, and values use rainbow parentheses: matching parentheses share a color, and nesting depths cycle through six colors. Strings, character literals, escaped symbols, and comments do not affect depth.

Tool argument names emitted with underscores are matched to declared hyphenated names, including nested objects and array items. If both spellings are present, the declared spelling takes precedence.

In fullscreen mode, a pending tool call starts with ▸. When it finishes, the same header shows a green ✓ for success or a red ! for failure. Errors appear beneath the original invocation and arguments. Background handoffs keep ▸ until completion. Thanks to @rgbcube for suggesting these outcome markers.

Autolith reports the session status over the interactive terminal using the OSC 7501 Program Status Protocol and app=autolith:

Status When reported
idle At startup or after cancellation
working During foreground input and resumed model turns
done or error After success or failure, until the next input or model turn
blocked For an input selector (kind=question), an approval (kind=permission), or authentication (kind=auth)

Reports include the conversation title. Progress from children and background jobs appears in the transcript. Reports omit prompt text, assignments, results, credentials, and progress estimates.

At startup, the boot screen shows a tip and the progress of opening the saved channel. Press Space or Enter to open the listener, or press Ctrl-C to quit. While you wait, the tip changes every ten seconds.

  • To skip the wait, use (setf (config :boot-screen-linger-p) nil) or set AUTOLITH_BOOT_LINGER to off for one launch.
  • To change the direct-session animation from 3.5 seconds, set :boot-screen-seconds or AUTOLITH_BOOT_DURATION. A hosted channel shows actual progress and does not replay the animation.
  • To skip the boot screen, use (setf (config :boot-screen-p) nil) or set AUTOLITH_BOOT_SCREEN to off. See (settings) for these options.

Almighty theme

Select the Almighty Lisp theme with (settings :terminal-theme :almighty). It uses the palette from almightylisp.com: near-white text on the site's blue, yellow for emphasis, cyan for code and strings, and an ALMIGHTY LITH boot mark. Terminals that advertise true color through COLORTERM get the exact colors; others get the nearest indexed or basic ones. The theme sets the terminal's default colors only while the viewport is active and restores them on exit. Save it for future launches with (setf (config :terminal-theme) :almighty); :autolith restores the default presentation.
