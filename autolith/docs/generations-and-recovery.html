Generations and recovery

Save a generation

Use (checkpoint) to save the running image as a retained generation. The source checkout must be clean and pass the project checks. Use (checkpoint :allow-dirty t) to include uncommitted source changes.

A checkpoint can wait for active work in other channels. Use (checkpoint-cancel) to cancel a waiting checkpoint.

Restore a generation

Run (generations) to find a retained image. Use (rollback "GENERATION-ID") to select it for startup, or launch it from the shell:

Shell 
autolith --recovery --list
autolith --recovery --generation GENERATION-ID

Recover from a crash

If Autolith resumes after a crash, read the diagnosis before asking it to retry the interrupted work.

To start a rescue session yourself, use:

Shell 
autolith open --pristine --permissions full

A pristine session skips private replay and executable initialization. Use it to inspect a startup problem without changing the selected generation.

Saved cores require the recorded SBCL version, OS build and architecture. To reconstruct without a core:

  1. Check out the revision in the generation manifest.

  2. Run ./script/bootstrap.

  3. Load Autolith in Lisp, then load the ordered reconstruct.lisp from the manifest in package AUTOLITH:

    Common Lisp 
    (asdf:load-asd (truename "autolith.asd"))
(asdf:load-system :autolith)
(load #P"/path/from/generation/manifest/reconstruct.lisp")
