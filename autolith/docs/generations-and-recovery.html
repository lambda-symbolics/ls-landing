Generations and recovery

Use (checkpoint) to save the live image as a retained generation. The source checkout must be clean and pass ./script/check on POSIX or script\check.ps1 on Windows. To allow local changes, use (checkpoint :allow-dirty t). Autolith marks the generation dirty because the recorded revision does not describe all of the source.

  • POSIX: You can keep using the active session while the image is saved.
  • Windows: Autolith saves the live heap and restarts through the stable launcher. It resumes the conversation after the saved image passes its probe.
  • World server: A checkpoint waits for running work and holds new turns. Use (checkpoint-cancel) to cancel a waiting checkpoint and release turns.

Run (generations) to list retained images. Run (rollback "GENERATION-ID") to select a compatible image and exit through recovery. In the terminal, (rollback) opens the picker. From the command line:

Shell 
autolith --recovery --list
autolith --recovery --generation GENERATION-ID

Pristine and retained-image sessions use separate world endpoints from the ordinary active image. A retained core must support world startup.

Automatic recovery uses a private clean checkout of the current committed source with --pristine. It uses a separate recovery core if valid and can fall back to source. Use explicit generation selection to return to an older compatible core.

After a fatal active failure, Autolith restores the terminal and writes a private crash capsule. Recovery resumes the conversation without duplicating scrollback. With a valid capsule, it queues one read-only diagnosis before ordinary input. The turn can inspect bounded crash context, workspace and tracked source, indexed source and active state. It cannot use shell, MCP, hosted-provider or image tools. It asks before applying a repair.

To start a rescue session yourself, use:

Shell 
autolith open --pristine --permissions full

A manual pristine session skips private image replay, mutation journal reconstruction and executable user initialization. Autolith enables --immutable and leaves mutation and conversation data on disk. Crash diagnosis requires a valid crash capsule from a supervised recovery.

Saved cores require the recorded SBCL version, OS build and architecture. To reconstruct without a core:

  1. Check out the revision in the generation manifest.

  2. Run ./script/bootstrap.

  3. Load Autolith in Lisp, then load the ordered reconstruct.lisp from the manifest in package AUTOLITH:

    Common Lisp 
    (asdf:load-asd (truename "autolith.asd"))
(asdf:load-system :autolith)
(load #P"/path/from/generation/manifest/reconstruct.lisp")
