Non-interactive jobs

Use run-job to run one child role from a script or CI. It uses the configured providers, MCP servers and role policies. Read the result from --output. Choose exactly one input form: --input FILE or --prompt TEXT.

Shell 
autolith --permissions auto run-job \
  --input /path/to/job.sexp \
  --output /path/to/result.sexp

The input file contains one data-only form:

Common Lisp 
(:autolith-job
 :version 1
 :id "job-identifier"
 :role "project-role"
 :prompt "Perform the assigned work."
 :input (:caller-owned "opaque data")
 :timeout-seconds 900)

For an inline assignment, pass --prompt TEXT or use --prompt - to read standard input. The defaults are role task, 86,400 seconds and a generated ID.

Shell 
autolith --permissions auto run-job \
  --prompt "Review the current change and report the result." \
  --role task --timeout-seconds 900 --id review-change \
  --output /path/to/result.sexp

Autolith atomically publishes an (:autolith-job-result :version 1 ...) artifact. Read :result for the response on :succeeded. Other terminal statuses are :failed, :cancelled and :timed-out. The result includes failure categories and any available trace and usage fields. Prompt read errors and oversized prompts produce a failure artifact too.

Headless jobs cannot ask for approval. auto denies decisions that require a prompt. sandbox permits only sandboxed shell commands. full permits full command execution and external tools that otherwise require a prompt. The child role still controls which tools it can call.

Live S-expression events

Add --events sexp to observe progress on stdout. Send diagnostics to a separate stream, and use the artifact for the authoritative result:

Shell 
autolith --permissions auto run-job \
  --input /path/to/job.sexp --output /path/to/result.sexp \
  --events sexp >events.sexp 2>diagnostics.log

Read consecutive top-level forms. Strings can contain newlines.

Common Lisp 
(:autolith-event :version 1
 :run-id "a-generated-run-uuid" :seq 1 :time "2026-10-08T09:00:00Z"
 :kind :run-started :data nil)
  • Sequence numbers increase within one run. A new run starts at one with a new run ID. There is no replay or reconnect cursor.
  • Event kinds are :run-started, :job-started, :tool-started, :progress, :tool-finished, :job-finished, :usage, :warning, :progress-omitted and :run-finished. Ignore unknown kinds. Events report registered tool names and bounded metadata, without prompts, tool payloads or output.
  • Root :job-finished and final :run-finished follow result publication. Published job events carry :result-uri. The final event reports :status and :published-p. It includes :output-path on publication. A write failure reports :category :result-publication-failed and exits nonzero.
  • A slow reader can miss events. :progress-omitted counts omitted progress, and a :warning with :code :queue-full reports lifecycle overflow. Execution and result publication continue even if the stream disconnects.

From Lisp, pass :events :sexp and :event-output STREAM to run-job-run. Read records with run-job-event-read-stream, which returns nil at EOF. The reader accepts bounded data forms of up to 16 KiB of UTF-8 per record. Use UTF-8 for character streams. Binary streams receive UTF-8 octets.
