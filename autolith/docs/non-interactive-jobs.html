Non-interactive jobs

Use autolith run-job to run an assignment from a script or CI. Pass either --input FILE or --prompt TEXT. Set the path for the result with --output.

Shell 
autolith --permissions auto run-job \
  --input /path/to/job.sexp \
  --output /path/to/result.sexp

The input file contains one data-only form:

Common Lisp 
(:autolith-job
 :version 1
 :id "job-identifier"
 :prompt "Perform the assigned work."
 :input (:caller-owned "opaque data"))

Pass --prompt TEXT for a prompt on the command line or --prompt - to read it from standard input. If you omit --id, Autolith generates a job ID.

Shell 
autolith --permissions auto run-job \
  --prompt "Review the current change and report the result." \
  --id review-change \
  --output /path/to/result.sexp

Check the status in the output file. If the status is :succeeded, read :result. If the job failed, read the error in the same file.

Choose the permission mode before you run the job. Headless jobs cannot prompt for approval.

  • auto denies operations that require approval.
  • sandbox only permits sandboxed shell commands.
  • full permits commands and external tools that would otherwise require approval.

Live S-expression events

Add --events sexp to observe progress on stdout. Send diagnostics to a separate stream, and use the artifact for the authoritative result:

Shell 
autolith --permissions auto run-job \
  --input /path/to/job.sexp --output /path/to/result.sexp \
  --events sexp >events.sexp 2>diagnostics.log

Read consecutive top-level forms. Strings can contain newlines.

Common Lisp 
(:autolith-event :version 1
 :run-id "a-generated-run-uuid" :seq 1 :time "2026-10-08T09:00:00Z"
 :kind :run-started :data nil)

Use the output file to check the final status. A slow or disconnected event reader can miss events.
