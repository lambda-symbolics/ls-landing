Install, update, and uninstall

Nix

To launch Autolith without installing a command, run:

Shell 
nix run github:lambda-symbolics/autolith

You can pass Autolith arguments after --. To get a command on your PATH, use nix profile install github:lambda-symbolics/autolith.

Nix supports x86-64 and ARM64 Linux and Apple silicon macOS. On first launch, the images are built under ${XDG_DATA_HOME:-~/.local/share}/autolith/nix/images/.

Linux, macOS, and BSD

Inspect the shell installer before you run it:

Shell 
curl -fsSL https://sh.lambda-symbolics.com/autolith | sh

The shell installer selects a package for your operating system and CPU:

  • Linux: x86-64 and ARM64, for glibc and musl
  • macOS: Intel and Apple silicon
  • FreeBSD, NetBSD, and OpenBSD: x86-64

Make sure that ~/.local/bin is on your PATH if you use the default command location. Install OpenSSL before running the script. On Linux, also install Bubblewrap (bwrap) for filesystem and network isolation.

Windows

On Windows x86-64, inspect the PowerShell installer before you run it:

PowerShell 
Invoke-RestMethod https://sh.lambda-symbolics.com/autolith.ps1 | Invoke-Expression

Restart Windows Terminal so that you can use the updated PATH. Sandboxed commands run in an AppContainer without network access. They can write to the workspace and a private temporary directory.

The SHA-256 of the release archive is verified before extraction on all platforms. See Release service for how archives are published.

Update

For a packaged installation, run autolith update and then start Autolith again. Use autolith update --help to see the command syntax. To update and restart from a running session, enter (update). Your original launch arguments are used for the restart. Automatic update checks run at most once every 20 hours.

For Nix, update the flake input or upgrade the package in your Nix profile. For a source installation, update the checkout and run the bootstrap command again.

Source checkout

  1. Install a compatible SBCL as specified in sbcl-minimum.version. Use AUTOLITH_SBCL to select a specific runtime.
  2. Install Quicklisp under ~/quicklisp, along with Rust, CMake, pkg-config, and OpenSSL. On Linux, install Bubblewrap as well.
  3. From the checkout, run ./script/bootstrap. Use ./script/check to check the build.
  4. Start Autolith with ./bin/autolith. To run it from other directories, link bin/autolith into a directory on your PATH.

Use --list to see test names, --suite NAME to select a suite, or --test NAME to select one test. You can repeat the selectors. For example:

Shell 
./script/check --suite workspace-resource --suite fixtures
./script/check --test test-workspace-file-resources --jobs 1

Use --jobs to set the number of workers and --timeout to set the time limit per worker in seconds. Selected runs skip the recovery checks.

Windows source checkout

  1. Install Git for Windows, Rust with the MSVC toolchain, and Quicklisp under %USERPROFILE%\quicklisp. Put clang on PATH for ColorLisp. You can use OpenSSL 3 from Git for Windows or set AUTOLITH_OPENSSL_DIRECTORY to the directory that contains it.
  2. From PowerShell in the checkout, run .\script\bootstrap.ps1. If there is no compatible SBCL, a runtime is downloaded and verified against the checksum in sbcl-windows-releases.sha256.
  3. Use .\script\check.ps1 to check the build. It accepts the same selectors as ./script/check.
  4. In Windows Terminal, start .\bin\autolith.cmd or .\bin\autolith.ps1.

Uninstall

  1. Stop running sessions.
  2. Run autolith uninstall. On Windows, delete the folders listed by the command. On other platforms, review the paths before confirming or pass --yes if no terminal is attached.
  3. If you used Nix, remove Autolith from the flake or profile. If you built a checkout, delete the checkout separately.

The installation, managed runtimes, built images, and caches are removed. Your conversations, memories, image commits, configuration, and credentials are kept.
